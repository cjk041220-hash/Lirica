## §3 维度详情与新发现

### 记忆动力学专题(用户点名复盘)

**复盘结论**:「一股脑全塞进去」**是历史问题,v0.4.2 已修**——记忆注入唯一通道是 pre_model_hook(agent/graph.py:80),每次 ≤5 条 × 200 字截断(<1K tokens),系统提示词不含记忆(test_soul 钉死)。本机 memories=0 行(5 份历史备份全部为 0 → 从未积累或被早期测试清空),臃肿是**前瞻风险**。真短板四条及处方:

| ID | 短板 | 灯 | 处方(本轮已落地) |
|----|------|----|--------------------|
| MEM-01 | 召回不看话题:相关路是全局热度/时近排序,聊天气和聊心事浮现同一批 | 🟠→🟢 | **B1 话题条件召回**:pre_model_hook 取末条 human 消息为 query,二段排序(共享二字词的记忆整体优先,层内 bigram overlap×1.0 + 原四因子)。设计修正披露:计划稿的 0.4 权重实测压不过新记忆的 recency+usage 双加成(1.3),且自然语言 query 的填充词会稀释 overlap——改为二值分层后「好想去澳门啊」能召回 10 天前的澳门记忆。passive 语义不变(正反馈闭环仍阻断,双钉回归) |
| MEM-02 | 记忆只增不减,无任何自动遗忘 | 🟠→🟢 | **B2 分层衰减**:active→core(access≥5 且 ≥30d)/ active→archived(≤1 且 ≥90d);挂 `_periodic_maintenance` 第三隔离段,零新 job;archived 是冷藏不是销毁(行还在库里) |
| MEM-03 | `access_count` 仅 recall 工具一个信号源,冷冷不主动问旧事则恒 0 | 🟡 | 本轮经 core 晋升间接缓解(被工具/对话反复触达的记忆有了晋升通道);信号多元化(remember 关联展示计弱热度)留作下轮 |
| MEM-04 | `status` 字段常年只有 active,`superseded` 死值 | 🟡→🟢 | core/archived 两个取值激活;v10 唯一索引谓词扩至 `IN ('active','core')`,manager.add ON CONFLICT + 读回 SELECT **三处逐字同步**(抽 `MEMORIES_INDEX_SQL` 三源共享常量,复刻 EVENTS_SCHEMA_SQL 纪律);superseded/滚动摘要按轻量原则本轮不做 |
