### 中等#2：旧的 `RoomMigrationTest` 错误基线仍残留（误导源）

- **位置**：`app/src/test/kotlin/.../RoomMigrationTest.kt:76-77`（`curiosity` / `warmth` 列）
- **问题**：该文件未被修改也未被删除，其手写 v1 schema 与 Room 导出的真实 v1（`1.json`）**结论互斥**，且它不使用 Room 实例打开验证（无校验力）。新增的 `MigrationTest.kt` 才是正确的那份。
- **影响**：已实际误导过一次评审（本报告第〇节）；未来任何读到这里的人或 AI 都可能再次得出"迁移不完整"的错误结论，甚至去"补 ALTER"导致真机 duplicate column 崩溃。
- **建议**：删除 `RoomMigrationTest`，或将其改写为引用 `1.json` 建库 + Room 实例打开（与 MigrationTest 合并更好）。同时建议在 `MigrationTest` 的防御断言注释里点名"旧测试基线错误"以免后人加回。

### 中等#3：失败回填可能使节流门失效（重试风暴）

- **位置**：`MemoryExtractor.kt:106-131`（触发条件与回填）、`:139-151`
- **问题**：触发条件含 `count >= minTurnsAccumulated(3)`。LLM 请求失败后整批回填 → 下一轮对话 `pendingTurns` 仍 ≥3 → **立即再次触发 LLM 请求**。若网络持续不可用，则**每轮对话都会发起一次必然失败的请求**，3 分钟/3 轮的双门控实质失效（本意是限流，回填后变成每次都打）。
- **影响**：弱网/断网时无谓的 LLM 请求开销（流量 + 电量 + 请求配额），与 P8"节流"目标相悖。
- **建议**：回填时递增失败计数，达到阈值（如 2 次）后：① 将 `batchStartTimestamp` 强制推后一个完整冷却期；② 或直接丢弃并记日志。保留"首次失败重试"的收益即可。

### 中等#4：屏幕尺寸取 `Resources.getSystem()`，多窗口场景不准

- **位置**：`XiaoxiApplication.kt:166-167`
- **问题**：`Resources.getSystem().displayMetrics` 返回系统级 Resources，不随应用窗口配置变化——在**分屏、自由窗口、折叠屏展开/折叠**等场景下拿到的是全屏尺寸而非应用实际窗口尺寸，接地比例换算与滑动坐标仍可能错位（虽然已比硬编码 1080×2400 好得多）。
- **建议**：优先用 `WindowManager.currentWindowMetrics`（API 30+，minSdk 26 需回退）；或让 `HelixGuiCoordinatorImpl` 在每次调用时通过 `XiaoxiAccessibilityService` 持有的服务上下文取 `resources.displayMetrics`（无障碍服务持有真实窗口上下文）。真机分屏场景验证一次。
