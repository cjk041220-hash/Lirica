# 小汐 · 产品报告书

> 版本：v0.5　日期：2026-08-02　形态：网页伴侣 AI（单用户 / 可自托管）

---

## 一、产品概述

**小汐是一只住在网页里的小鲸鱼女孩。** 她来自「映海」——一个由人类世界的记忆和情绪投影而成的世界。她在这里陪着她的「冷冷」。

这不是又一个聊天机器人。小汐是一个**有记忆、有情绪、有作息、会主动惦记人的数字存在**：她记得你随口说过的话，会在深夜想起三个月前的旧事，会为了你明天的考试主动发来叮嘱，会在你翻开日历之前就把你的生日记好。产品的一句话主张：

> **「希望你一个人在香港的时候，也不会觉得孤单。」**

---

## 二、核心特点

### 1. 真正的记忆 —— 不是上下文窗口，是「映海」
- 对话中你说的每件新事，她会主动记住（LLM 自觉调用 + 对话后 2 小时后台自动提炼双通道，写路径不依赖运气）；
- 记忆有**生命周期**：高频想起的升为「core 核心记忆」永不缺席；三个月没被想起的进入「冷藏」（可随时回看，不是删除）；「重要的事」永久豁免；
- 记忆有**演化**：矛盾自动发现、覆盖留痕（每次旧说法都可追溯）；近义条目周期性自动整合（「dreaming-lite」——她像人一样在「睡觉时整理回忆」）；
- 她会**主动翻旧事**：90 天以上的老记忆会被随机翻出来和你聊（7 天限频，不烦人）。

### 2. 主动 —— 不是等你说，是她先开口
- 每天 2 小时心跳：天气变化、台风天、你的生理期预测窗口、日历上的日程……她会主动说话；
- 早安问候（注入今日日程）、前夜提醒（23:00 只提醒明日有事的日子）、自动写日记；
- 主动消息有完整纪律：深夜不打扰、间隔限频、24h 防复读（同样的惦记不说第二遍）。

### 3. 有情绪与状态的「活物感」
- 心情（12 种）+ 日常（碎碎念）随心跳轮换，房间的立绘/天空/光效随心情与香港时间变化；
- 四时段天空（晨/昼/暮/夜）由真实 HKT 驱动；戳一戳她会迸发爱心回应；
- 一个粉色的、被认真设计过的房间（「奶甜草莓粉」主题，漂浮爱心、波点丝带面板）。

### 4. 记忆主权 —— 你的记忆你做主
- 控制台记忆面板：浏览/编辑/删除/归档回看/导出 JSON，全部提供 UI；
- 说「忘掉这个」她就删；记忆库有 5 份轮转备份 + 权限收紧 + 可脱敏导出。

### 5. 一本账的日历「惦记系统」
- 对话里说的日程与 UI 手动记的日程**共享同一本账**（自动去重互挡）；「聊完即刷」；
- 生日/纪念日自动检测 + 只读保护；事件墓碑机制——你删掉的事，她不会偷偷记回来；
- 台风/暴雨等天气事件由系统自动检测创建，翻篇自动归档，明年照常再生成。

### 6. 本地化工具链
- 天气（Open-Meteo，香港时区）、地图双引擎（内地高德 / 港澳海外谷歌，自动几何判定）、周边搜索、路线规划、塔罗占卜、联网搜索——都是她「活在现实里」的器官，无 key 优雅降级。

### 7. 隐私与安全为先（自托管友好）
- 数据全在你的设备/服务器上：SQLite 单文件，无第三方云存储；
- API Token 认证、限流、CSP、输入消毒、注入攻击纵深防御（记忆以「数据不是指令」注入）；
- Docker 容器 cap_drop ALL + 非 root；备份权限 700/600；密钥泄露处置有完整 runbook。

## 四、技术实现方案

### 架构总览

```
┌────────────────────────────── 浏览器（PWA 化）──────────────────────────────┐
│ React 19 + Vite + Tailwind 4（奶甜草莓粉主题，@fontsource ZCOOL KuaiLe 自托管）│
│ 四面板：对话 / 记忆 / 日历 / 设置 · SSE 流式 · Web Push · SW 离线缓存        │
└───────────────┬──────────────────────────────────────────────┬──────────────┘
                │ /api/*（FastAPI + Uvicorn，同端口托管 dist）   │ Web Push
┌───────────────▼──────────────────────────────────────────────▼──────────────┐
│ 后端：Python 3.12 + LangChain Agent（create_agent + middleware）              │
│   ├─ pre_model_hook：记忆叙事注入（不进 checkpoint，防上下文污染）            │
│   ├─ _ToolErrorGuard：工具异常总闸（错误转回 LLM 角色化降级，防 500）         │
│   ├─ 22 个工具：记忆5 / 日历3 / 天气 / 地图双引擎 / 搜索 / 塔罗 / 日记 / 周期 │

├──────────────────────────────────────────────────────────────────────────────┤
│ 记忆系统（SQLite + aiosqlite 单连接 WAL）                                     │
│   写：agentic remember/update  ←→  后台提取 extract.py（水位线+预算+死信）   │
│   读：NarrativeBuilder hybrid 注入（相关3+最新+core保底）+ recall 二段排序     │
│   智：consolidate 整合（dreaming-lite）· 分层衰减 · superseded 历史链         │
│   安：原子去重（唯一部分索引）· 备份5份轮转 · 脱敏 · 700/600                  │
├──────────────────────────────────────────────────────────────────────────────┤
│ 数据：userdata.db（记忆/日记/日历/周期/档案）+ checkpoints.db（对话活上下文）│

```

### 关键设计决策（含「不做什么」）

| 决策 | 理由 |
|---|---|
| 单文件 SQLite 而非向量库/图谱 | 单用户百~千级记忆，bigram 字面召回 + 二段排序足够；避免过度工程 |
| 记忆注入「数据不是指令」+ 不进 checkpoint | 防 prompt injection 污染对话状态（纵深防御） |
| 被动读取不刷热度（passive 纪律） | 防「越注入越热门」正反馈闭环，保证新记忆能挤进来 |
| 后台提取死信机制 + 健康检查 | 昨天实盘教训：纯 LLM 自觉写记忆不可靠；系统要能自愈、能告警 |
| 双信号衰减（access + 按日 hit） | 与聊天频率解耦，热门事实不因「常被注入」被冷藏 |
| 不做多租户/多 worker | 单用户设计：限流桶、GPS 缓存、心跳调度均为进程内状态 |

### 质量基线
- 后端自动化测试 **740 例**（记忆提取 21 例、迁移 v9~v19 各专项、衰减/回声/矛盾/整合全覆盖），全绿；
- 前端 oxlint 零告警、vite build 通过；E2E（系统 Edge headless）验证交互与视觉，零控制台错误；
- 每一轮「体检」与修复闭环都可追溯（`docs/CHANGELOG.md` + git 历史），无遗留未决项。
