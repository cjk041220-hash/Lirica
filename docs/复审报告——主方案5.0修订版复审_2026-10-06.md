## 三、新发现问题（按优先级）

### R1（高 · 技术事实错误）：手电筒权限写错
§4.1 表格给 `ToggleFlashlightAction` 标注所需权限 `CAMERA`。**`CameraManager.setTorchMode` 自 API 23 起无需任何权限**——这正是系统引入该 API 的意义。

照表实现会造成两个实际伤害：
1. `PermissionManager` 误加 CAMERA 体检项；
2. `AndroidManifest` 误声明 CAMERA 危险权限——触发运行时权限弹窗、商店审核问题，且系统会判定应用占用相机。

**修正**：权限列改"无（API 23+）"，并补注"设备相机被占用时 `setTorchMode` 返回 false，需处理失败分支"。

### R2（高 · 事实错误 + 不变量矛盾）：SendSms 行
两处问题：

1. **权限错**：`ACTION_SENDTO`（smsto: 预填草稿）**不需要 SEND_SMS 权限**——SEND_SMS 是 `SmsManager` 直发通道才需要的权限。现网 `IntentActionDispatcher.kt:24-29` 正是 SENDTO 预填形态（打开短信 App、预填正文、用户手动按发送）。权限列应改"无"。
2. **与 §1.2 矛盾**：§1.2 零破坏不变量写"非幂等外部通信（如替用户发送 SMS/邮件）**一律物理熔断**"，§4.1 表格却给 SendSms "中危 + 二次确认放行"。闸门回归用例（DoD 第 2 条的 N 个固化用例）必须从不变量推导，两处不一致会让验收基准无法编写。

**修正建议（二选一，建议前者）**：
- 把 §1.2 措辞精确化："**不经用户确认的自动发送**（SmsManager 直发 / 无确认提交）一律物理熔断；**预填草稿类**（SENDTO / 拨号盘）降为中危 + 二次确认正文"；
- 或 SendSms 行改 PhysicalBlocked。

### R3（低）：SendEmail 缺席权限表
§4.1 表格 7 行中 SendSms 进了、SendEmail 没进。补一行：`ACTION_SENDTO` mailto:、中危、无权限、与 SendSms 同策略。

### R4（中 · 实现期待验证）：TYPE_TOUCH_INTERACTION_START 可见性
§6.2 用户抢占检测依赖 `AccessibilityEvent.TYPE_TOUCH_INTERACTION_START`。该事件对无障碍服务的分发条件（服务需声明何种 capability）与国产 ROM 上的可靠性**均未验证**。

**建议补两句**：
1. M5.2 真机验证清单加入"抢占事件在 MIUI/HyperOS 等国产 ROM 上的可达性"；
2. 写明降级备选——事件不可得时，退化为"每步 Observe 时检测前台包名/页面指纹突变 + `dispatchGesture` 完成回调异常"的组合判断。

另外，"用户停止操作 5 秒自动恢复执行"建议改为**默认不自动恢复**（等待显式"继续"点击或对话确认），5 秒自动恢复仅作可配置项——**用户停手 ≠ 用户同意继续**。

### R5（中）：M5.4 无资源开销验收
§10.2.4 内存 ≤15MB 只写了 M5.1~M5.3。M5.4（虚拟副屏）必须有独立基线，否则副屏一开即破线却"不算违约"——一个 1080p VirtualDisplay + ImageReader 缓冲就约 8MB。

**建议补一行**："M5.4：虚拟副屏激活期间内存增量 ≤40MB，仅漫游模式激活，任务结束即释放。"

### R6（低）：PermissionManager 扩展未进 M5.1 交付清单
§4.1 表格列出了 WRITE_CALENDAR（运行时权限）与 WRITE_SETTINGS（特殊权限，需系统设置页手动授权），但 M5.1 交付清单第三条没有对应落地项。

**建议补**：`PermissionManager` 新增日历、WRITE_SETTINGS 两项体检 + Onboarding/Settings 引导修复（沿用现有六项体检模式，见 `common/permissions/PermissionManager.kt`）。

### R7（低）：SafetyPolicyEngine 层级归属澄清
§三架构图把它画在 Layer 2，§4.1 又要求注入 Layer 1 的 `dispatch()` 入口。建议加一句："它是被 Layer 1 通道入口与 Layer 2 编排共同调用的独立裁决服务"，避免实现者把它收进 orchestration 包、导致 Layer 1 某条通道漏调。

### R8（低 · DoD 补强）
§5.1 定义了 VLM ≤5 次、§九定义了 Macro 命中率，但 §10.2 DoD 未收口这两项。建议 DoD 补两行：
- M5.2："单任务 VLM 调用 ≤5 次，且 ExecutionTrace 记录每次调用"；
- M5.3："Macro 回放起始页核验通过率与命中率输出真机实测数据"。

另建议 §九 ExecutionTrace 补 per-task token 消耗字段——方案承诺"后续根据实际 Token 消耗数据做动态预算"，没有 token 埋点该承诺无法兑现。
