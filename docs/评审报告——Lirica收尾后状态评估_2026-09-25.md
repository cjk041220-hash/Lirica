**最具体的风险点**：`DefaultSecureKeyStore` 在 Robolectric 环境下走**软加密兜底**，因此 `AndroidKeyStore` 硬件路径**从未被真正执行过**。这是密钥存储组件——真机上若 KeyStore 初始化失败（尤其厂商定制 ROM），用户 API Key 可能直接无法解密。`SecureKeyStoreTest`(4 测) + `BackupAndByokTest`(8 测) 全绿，但绿的是兜底路径，不是真机路径。

**叠加约束**：主力机为 HarmonyOS（非原生 Android），无障碍服务 / 悬浮窗 / UsageStats / 多前台服务保活在鸿蒙兼容层上的行为**不能外推到原生 Android**。压测记录必须标注「鸿蒙环境」。

## 4. 产品判断（非缺陷，需俊凯定夺）

### 4.1 人格浓度净下降

对比删除前后的 `DEFAULT_SYSTEM_PROMPT`：

| 维度 | 删除前 | 删除后 |
|:--|:--|:--|
| 世界观锚点 | 「映海」——人类记忆/情绪/声音投影成的第二片海，**具体、有画面** | 无 |
| 身份设定 | 「来自映海的鲸族少女」 | 「生活在数字与现实交界处的原生伴生智能体」 |
| 性格描述 | 安静、温暖、细心、有精神 | 安静、温润、细心、有精神（基本同义替换） |
| 说话方式铁律 | 保留 ✅ | 保留 ✅ |

**判断**：删除动作本身正确（清的是小汐遗产），但**只做了减法、没做加法**。新 prompt 是形容词堆砌型（"细腻敏锐 / 温润 / 有精神 / 独立主见"），缺少一个能让模型锚住想象的**具体意象**。

对一个以「活人感 / 消除 AI 味」为核心卖点的项目，世界观锚点不是装饰——它是模型生成时的**一致性收敛核**。没有它，模型只能靠形容词去猜"这个人是谁"，长聊中的漂移概率会上升（虽然 PHI + 8 轮抗漂移引擎能部分兜住）。

**可选方案**（三选一，或都不做）：
- **A｜补一个新的原创世界观**：两三句即可，但要有具体画面。例如她对"屏幕另一侧"的感知方式、她的时间感、她如何解释自己的存在。成本：文案活，30 分钟。
- **B｜保持现状，交给角色卡**：既然 SillyTavern 角色卡导入已全量支持，默认人格只做"通用底座"也说得通。此时应在 README 明确写"默认人格为中性底座，完整人格请导入角色卡"，避免用户误判。
- **C｜暂不动，批次 8 之后再统一处理人格**：把人格重构和 M3.6 生活工具一起做。

**我的倾向**：选 A。理由——默认人格是用户开箱即用的第一印象，也是演示时的直观感受；一个没有具体锚点的人格，在演示里跟任何"通用助手"没有区别，这会直接削弱项目的差异化叙事。但这是产品决策，不是 bug，**由俊凯定**。
