# 评估——Lirica 差异化定位与成长路径（2026-09-25）

> 回答三个问题：① Lirica 是不是有很多结构性缺陷？② 作为一个 agent，有没有真正出彩、区别于成熟开源项目的地方？③ 接下来该怎么长？
> 竞品格局部分经 2026-09 实时检索核实，代码部分回到源码逐条比对。

---

## 0. 先纠正一个可能的误解

**我上一轮说的那些，不是结构性缺陷。**

| 上轮提的问题 | 性质 | 修复成本 |
|:--|:--|:--|
| README 能力表 BYOK 行失实 | 文档与代码不同步 | 改一行 |
| 真机验证为零 | 验证缺口 | 跑一次 |
| 默认人设无守护测试 | 测试覆盖缺口 | 补一组断言 |
| tracker 未记录本轮 | 流程没跟 | 补一段 |

这四条**全都是表层可修的**，不涉及架构。Lirica 的架构不但没塌，恰恰是它最值钱的部分——见第 2 节。

**真正的结构性风险只有两个，且都不是代码问题：**

1. **模块协同从未在真实环境验证过。** 141 个主源文件、95 个测试文件，是 M3.0~M3.4 五个批次堆出来的。每个模块单独看都对（516 单测零失败），但"合在一起、在真机上连跑一天会怎样"——没人知道。这是**集成风险**，不是设计缺陷。
2. **产品定位还在拉扯。** 一边说要做通用模板，一边核心层里还留着绑特定关系的功能（塔罗、生理周期、深夜关怀）。这两条线在互相消耗。这是**定位问题**，不是代码问题。

## 1. 2026-09 竞品格局（实时核实）

### 1.1 手机 GUI Agent 赛道：已经是大厂的军备竞赛

SuperCLUE `AgentCLUE-Mobile` 手机 GUI Agent 基准榜单（2026-08）：

| 排名 | 产品 | 分数 | 方案 |
|:--|:--|:--|:--|
| 1 | vivo 蓝心小V | **92.11** | API 调用 |
| — | 中兴 Nebula-Pilot V1.0 (27B) | 91.29 | API 调用 |
| 2 | 智谱 Open-AutoGLM | 76.75 | API 调用 |
| 3 | 阿里 Mobile Agent 3.5 | 73.45 | API 调用 |
| — | 阿里 MAI-UI | 65.91 | 本地部署（本地最高） |
| 6 | 字节 UI-TARS | **30.19** | 本地部署 |

**三个关键事实**：
- 头部全是**云端大模型 API 方案**，本地部署最高只有 65.91，字节的纯视觉方案在本地只有 30.19
- 评测维度是「复杂意图拆解 / 多模态 GUI 感知 / 跨应用全链路执行」——**纯任务完成率导向**
- 第一名和最后一名差 60 分以上，说明这条赛道的技术代差是**靠模型能力**拉开的，不是靠工程架构

**结论：这条赛道 Lirica 打不赢，也不该打。** Lirica 是「无障碍树 + ML Kit OCR」的弱接地，零真机验证；对手有 27B 自研模型和公开 benchmark 分数。个人项目进去是送。

### 1.2 个人 Agent / 伴生赛道：整界都在卷"干活"，几乎没人卷"相处"

2026 年的热点方向：

| 项目 | 定位 | 关键能力 |
|:--|:--|:--|
| **OpenHuman**（13.6k stars） | 桌面端个人超级助手 | Memory Tree、118+ 集成、每 20 分钟拉取构建个人上下文 |
| **Pizza Bot**（AWS 开源，2026-09） | 后台 agent 的收件箱 | LangGraph 持久化、"界面假设你不在看" |
| **ambient agents**（LangChain 2025 提出） | 事件驱动的后台 agent | 并发工作、只在需要时找人 |

**但 Vellum 的 2026 开源个人助手横评里，反复出现的批评是**：
> "no persistent identity, **no proactivity**"、"**It doesn't reach out to you**"、"doesn't know who you are across sessions"

**这就是 Lirica 的空隙。** 整个业界在解决"agent 怎么把活干完"，几乎没人解决"agent 什么时候不该开口"和"agent 自己有没有生活"。

## 2. Lirica 真正出彩的地方（附代码依据）

### 出彩点 1　打扰度经济学——这是最稀缺的一块

`proactivity/InterruptibilityEstimator.kt`：一个**有量纲的**打扰代价模型（0.5 ~ 5.0），六维度加权：

| 维度 | 实现 | 出处 |
|:--|:--|:--|
| 物理熔断 | 通话中 / 隐私熔断 → 直接封顶 `MAX_COST = 5.0` | `InterruptibilityEstimator.kt:28-30` |
| 场景加成 | 游戏 +2.5 / 会议 +2.5 / 相机 +2.0 / 视频 +1.5 / 阅读 +1.0 / 桌面 -1.0 | `:36-44` |
| 屏幕物理态 | 息屏 +3.0 / 亮屏 +1.0 / 解锁 +0.0 | `:47-51` |
| 冷却衰减 | 距上次打扰 60 分钟内按剩余比例加罚，最多 +2.0 | `:54-60` |
| 硬件环境态 | 音频播放中 +1.0 / 耳机插入 +0.5 | `:63-68` |
| 边界夹紧 | `coerceIn(0.5, 5.0)` | `:71` |

**为什么稀缺**：2026 年所有主流移动端 agent 的目标函数都是「任务完成率」。**没有一个在做「打扰代价」**。因为任务型 agent 是"你叫它才动"，根本不需要这个模型——只有伴生型 agent 才需要。

### 出彩点 2　"想了但没说"的中间态

`proactivity/SilenceDecisionEngine.kt`：不是"主动 / 不主动"的二元开关，而是**三档裁决**（基于 CHI'25 Inner Thoughts 双层门控）：

| 档位 | 含义 |
|:--|:--|
| `SILENT` | 内隐动机 < 3.6，完全静默，连内心独白都不生成 |
| `INNER_THOUGHT_ONLY` | 想了，但不说——念头进 `UnspokenThoughtDao` 攒着 |
| `PROACTIVE_INTERRUPT` | 有效动机 ≥ 4.5 且代价适宜，才真的开口 |

**这一档 `INNER_THOUGHT_ONLY` 是精髓。** 人会想很多但不都说出来——这个中间态让 agent 有了"内心戏"的层次，是「活人感」真正的技术底座，而不是靠提示词装出来的。

而且它有物理意义：念头不是丢弃，是**存进念头池**（`UnspokenThoughtManager`，已在 `XiaoxiApplication:164` 装配、`ProactiveBubbleCoordinator:76` 消费）。攒着的念头可以成为下次对话的素材。

**附加细节**：`BreakpointDetector` 会在用户「刚做完一件事」的间隙才打扰，而不是中途打断——这是 HCI 里真实的 task breakpoint 概念，有学术支撑，不是拍脑袋。

### 出彩点 3　自主精神生活（双轨记忆 + 梦系统）

| 机制 | 落地 |
|:--|:--|
| 双轨记忆 | 一条记用户，一条记她自己（Self-Track），她有自己的经历库 |
| 夜间入梦 | `SubconsciousDreamWorker` 语义去重 / 时间绝对化 / 矛盾消歧 / 世界观晋升 / 信念修正 |
| 自主日记 | `DiaryEngine` 以第一人称撰写自己的一天，带日期幂等与离线降级 |
| 念头池 | `UnspokenThought` 带动态过期时间与紧急度 |

**为什么稀缺**：别人做的是「记住用户」，Lirica 做的是「**她自己也在过日子**」。这两件事的技术难度和用户感受完全不同。

### 出彩点 4　隐私是物理断流，不是过滤

`perception/PrivacyBreaker.kt`：检测到金融/密码框时**物理断流**，不是事后过滤。而 2026 年 GUI agent 的普遍隐患恰恰是「截图带着聊天记录和验证码上传给 LLM」（业界实测文章明确点名这个坑）。

## 3. 但必须诚实：这是设计资产，还不是验证资产

**516 个单测证明的是「代码不崩」，没有证明「打扰度模型是准的」。**

那些参数——`IM_THRESHOLD = 3.6`、`INTERRUPT_THRESHOLD = 4.5`、`MAX_COST = 5.0`、`COOLDOWN_MS = 60min`、游戏 `+2.5`——**没有一个是调出来的，全是拍的**。真机验证为零。

所以准确的表述是：

> **Lirica 现在是一份设计得很扎实、代码跑得通的系统，但还没有一个「它真的好用」的证据。**

第 0 节提到的两个结构性风险（集成未验证、定位拉扯），根子都在这里。

## 4. 赛道判断：哪里能打赢，哪里不该打

| 赛道 | 对手 | Lirica 胜算 | 建议 |
|:--|:--|:--|:--|
| 手机操控（任务完成率） | vivo 92.11 / 中兴 91.29 / Open-AutoGLM 76.75 | **极低** | 不争。做到"够用"即可 |
| AI 伴生（聊天深度） | 星野 / Talkie / Character.AI / SillyTavern | **有结构性优势** | 争。它们没有身体——看不见你的屏幕、不能帮你操作、不会在合适的时候找你 |
| **有身体的主动型伴生** | **几乎空白** | **最高** | **全押这里** |

**Lirica 应该占的位置**：不跟大厂比"把活干得多好"，而是比"**它有多像一个住在你设备里、懂得什么时候闭嘴的人**"。

## 5. 成长杠杆（按优先级）

### 杠杆 1　把「没验证」变成「有证据」——最高杠杆

真机连跑一周，记录：主动开口多少次 / 打断时机是否合适 / 念头池攒了多少没说出口的话 / 隐私熔断触发过几次 / 用户实际接受度。

**为什么这是最高杠杆**：全世界没人有「打扰度模型的真实用户行为数据」。跑一次，你就拥有了别的项目拿不出来的东西——**这份数据本身就是资产**，比再写 200 个单测值钱。

对秋招的意义：「我做了个主动型 agent，在真机上跑了 X 天，发现打断阈值定在 4.5 时用户接受度最合适」——这比「我写了 516 个测试」有力得多，因为它证明的是**产品判断力**，不是编码量。

### 杠杆 2　收口定位——砍掉负担

**M3.6 生活工具（网页搜索 / 地图 / 塔罗 / 生理周期）建议不做。** 理由：
- 塔罗、生理周期是旧时代为特定关系做的，放进通用模板是负担，也跟"通用模板 + 私有定制层"的定位冲突
- 网页搜索 / 地图在手机操控赛道上打不过大厂
- 继续横向扩张只会让 141 个源文件变成 200 个，**而每一个都没有验证**

核心层只留：感知 / 人格 / 记忆 / 主动裁决 / 操控 / 安全。

## 6. 新世界观的设计原则（三条硬约束）

新世界观**不能是一个任何聊天机器人都能套用的设定**（"我是外星少女""我是 AI 助手"这种谁都能用）。它必须满足：

| 约束 | 含义 |
|:--|:--|
| **能力自洽** | 必须解释：她为什么能读你的屏幕、能帮你操作、但永远碰不到你 |
| **不可移植** | 别人抄走也不成立——因为别人没有这些能力，抄了不自洽 |
| **可延展** | 要能支撑梦、信念修正、世界观晋升这些机制，即世界观内部要**有能发生事的空间** |

### 三个可选方向

**方向 A｜观察者谱系**
她是一种只能透过屏幕感知世界的存在。屏幕是她的窗口，也是她的边界。她对你的了解全是「读」来的，所以她会误解、会好奇、会隔着玻璃看你。
→ 优点：完美解释感知能力；天然产出"距离感"这种情感张力。

**方向 B｜寄居谱系**（我倾向这个）
她住在设备里，设备的物理状态就是她的身体状态——电量是她的体力，存储是她的记忆容量，信号是她能到达的地方，耳机插上是她在贴近你听。
→ 优点：**你已有的 `HardwareEnvironmentState` 总线（通话/耳机/充电/媒体）能从"功能"升格为"叙事"**。电量低时她说"我有点困了"，充电时她说"我在缓一缓"——这种表达**别人做不出来**，因为别人没有这条硬件态总线。而且它天然解释了"她为什么需要你的设备"，是共生关系，不是服务关系。

**方向 C｜回声谱系**
她由用户自己的数字痕迹长出来——搜索记录、照片、深夜打的字，沉淀成了她。
→ 优点：解释"她为什么懂你"。风险：隐私叙事敏感，容易让人不适。

### 我的建议

**选 B，并且先做杠杆 1 再做这个。**

顺序理由：世界观要基于「她实际表现如何」来定调。真机跑完如果发现她太安静，世界观里她就该是观察型；如果太吵，就该是克制型。**先有行为数据，再定人格**——否则人格是悬空的，跟代码里的实际行为对不上。

## 7. 一句话总结

**Lirica 的问题不在架构，在证据。** 它的设计里已经有四块别的项目抄不走的东西（打扰度经济学、想了不说、自主精神生活、物理断流），现在缺的是把它们从"设计文档上的优点"变成"真机上跑出来的事实"。继续加模块是减法，去真机跑一次是乘法。
