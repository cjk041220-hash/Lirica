# 一、 战略重构与产品全景画像

### 1.1 破茧重构：为什么彻底推翻 1.0 的“专属礼物”设定？
小汐 1.0 最初诞生于特定的人物背景与羁绊（冷冷与 JK、香港留学、鲸族少女），其业务逻辑、系统提示词与交互逻辑严重与单一实体耦合。这导致了三个致命的工程与体验瓶颈：
1. **角色僵化，无法泛化**：新用户无法代入其他角色，任何尝试更改世界观的行为都会与底层硬编码的逻辑冲突。
2. **被动交互与容器受限**：原本的形态是一个类似 Web 抽屉的聊天盒，用户不主动点开，它就只是躺在后台的死程序，毫无“生命感”与“存在感”。
3. **能力与系统脱节**：无法利用 Android 系统底层丰富的能力（通知流、前台应用、无障碍树、屏幕画面、物理手势），AI 无法真正感知用户在手机上的真实生活，更无法替用户操作手机。

### 1.2 新产品全景画像（四大支柱）
* **自由自主人格（Customizable & Autonomous Persona）**：全面兼容行业事实标准 **SillyTavern（酒馆）角色卡（V1/V2/V3）**。它可以是傲娇青梅竹马、毒舌游戏搭子、温柔生活管家、严厉健身教练或赛博黑客。最关键的是——**它拥有自己的生活经历、情绪起伏和未完成念头，绝不沦为迎合用户的谄媚机器**。
* **获权“视奸”感知（Ambient Context Awareness）**：在用户明确授权的前提下，Agent 宛如趴在用户手机屏幕边上的小精灵。它能感知用户当前在用什么 App、停留了多久、屏幕上的图文内容、收到了什么通知，并在合适的情境下给出极具角色特征的反应。
* **真实设备操控（Phone Manipulation & Action Grounding）**：具备“动嘴也能动手”的执行力。从基础的打开 App、导航、放歌，到高级的跨应用信息检索、发送微信草稿、自动化打卡。
* **隐私优先与完全去中心化（BYOK & Local-First）**：无中心化服务器，不收集用户隐私。用户自备 API Key（BYOK），所有记忆数据库、配置文件、截屏感知分析均在端侧闭环处理，直连大模型端点。

# 二、 前沿理论与开源标杆深度借鉴

在方案设计过程中，我们深入调研了近两年 Android 端侧智能体及多模态 GUI 操控的前沿项目：

### 2.1 [AAswordman/Operit](https://github.com/AAswordman/Operit) 的工程启示
[AAswordman/Operit](https://github.com/AAswordman/Operit) 是目前 GitHub 上最成熟的原生 Android AI Agent 开源项目之一，其架构为我们验证了如下核心工程规律：
1. **Kotlin 纯原生才是移动端智能体的正确形态**：Operit 采用 **Kotlin + Jetpack Compose** 构建，避开了在 Android 虚拟机内运行完整 Python 环境带来的兼容灾难，冷启动毫秒级，后台常驻内存占用极小。
2. **阶梯式提权控制体系（Graduated Privileges）**：
   * **Level 1（AccessibilityService 无障碍）**：零门槛，用户系统设置开启即可。直接读取当前窗口 UI 树（`AccessibilityNodeInfo`），通过 `dispatchGesture` 模拟点击、滑动。
   * **Level 2（Shizuku / 无线 ADB）**：免 Root 获得 Shell 权限，可执行精准触控、后台跨应用唤醒与深层控制。
   * **Level 3（Root）**：内核级事件注入与环境完全控制。
3. **解耦的工具体系（MCP 与 ToolPkg）**：支持 Anthropic MCP（Model Context Protocol）协议，将手机硬件与系统能力标准化为工具库。

### 2.2 [zai-org/Open-AutoGLM](https://github.com/zai-org/Open-AutoGLM) 与 [bytedance/UI-TARS](https://github.com/bytedance/UI-TARS) 的视觉操控突破
旧计划曾悲观认为“移动端 GUI 自动化成功率不足 10%”，但调研表明，基于专用模型和混合架构，端侧操控已进入实用阶段：
* **混合架构（Hybrid Tree + Vision）**：纯无障碍树会死在 Flutter、Unity 游戏或 Webview 上；纯视觉由于模型漂移和分辨率问题计算开销巨大。最新行业方案是：**优先抓取无障碍树（零 Token、零延迟获取绝对边界与文本） $\rightarrow$ 无障碍树缺失或复杂界面时降级为屏幕截屏，交由 VLM（如 AutoGLM-Phone-9B 或 UI-TARS）做视觉坐标预测**。
* **反思与校验闭环（Reflection Loop）**：每个动作（Click/Swipe/Type）执行后，自动抓取下一帧状态与上一帧对比，判断操作是否成功生效，若失败则触发重试或回退。

### 2.3 角色卡规范与主动伴生理论
* **[kwaroran/character-card-spec-v3](https://github.com/kwaroran/character-card-spec-v3)**：SillyTavern V3 规范明确了 `post_history_instructions`（PHI 语气重锚）、`character_book`（世界书词条触发）的标准解析方法。
* **主动打扰度仲裁（Agent-Judged Silence）**：主动发声绝不能是固定频率的骚扰。必须基于“打扰度模型”：全屏游戏/看视频时静音，切换应用闲逛时轻搭话，深夜长久不睡时关切提醒。

# 三、 核心路线决断：跳出 Chaquopy 陷阱，拥抱 Kotlin-First

### 3.1 为什么必须坚决放弃“Chaquopy + LangGraph”？
在原《开发总纲》中，Phase 0 列出的最大阻断性风险是：*L1: Chaquopy 能否跑通 `langgraph + pydantic-core`*。**经过深度代码审阅，这个技术假设是必须立即纠偏的弯路**：
1. **原生扩展灾难**：`pydantic-core`、`tiktoken` 均基于 Rust 编译，在 Android ARM 架构的 Chaquopy 编译轮子里常年存在 ABI 缺失或符号冲突。
2. **内存与后台保活死刑**：Chaquopy 启动需要初始化 Python 运行时，冷启动耗时 3~5 秒，打包体积凭空增加 80MB+。在 Android 系统的 Low Memory Killer (LMK) 机制下，后台常驻的 Python 服务极易被系统瞬间杀死。
3. **JNI 跨语言往返的性能泥潭**：如果 Agent 在 Python，而无障碍、截屏、悬浮窗、通知监听在 Kotlin，每一个感知事件和手势指令都要跨越 JNI 桥接序列化传递，延迟将从毫秒级放大至秒级。
4. **现有资产的真相**：阅读 `backend/memory/manager.py` 和 `heartbeat_moods.py` 会发现，小汐沉淀的核心算法（时间衰减记忆评分、Russell 情绪空间漂移、反 AI 腔正则、8 轮重锚）**全都是纯数学公式与字符串模板**！在 Kotlin 中用协程重构它们，只需要几百行非常清晰优雅的代码。

### 3.2 技术栈选型决断
* **宿主与核心引擎**：**100% Native Kotlin**。
* **UI 表现层**：**Jetpack Compose**（主界面） + **Compose-based Overlay**（跨应用桌面伴生悬浮窗）。
* **异步与响应式并发**：**Kotlin Coroutines + StateFlow / SharedFlow**。
* **本地数据与记忆存储**：**AndroidX Room (SQLite)** + AES-256 加密。
* **网络与大模型流式**：**Ktor Client / OkHttp + Server-Sent Events (SSE)**，原生处理 Token 级流式与 Tool Call 增量拼装。
* **权限与系统能力**：`AccessibilityService`、`MediaProjection`、`NotificationListenerService`、`UsageStatsManager`、`Shizuku API`。

# 五、 关键子系统深度设计

## 5.1 自由人格与抗漂移心智中枢（The Mind Engine）

### 5.1.1 SillyTavern 角色卡协议全面接管
系统原生内置二进制 PNG 读取引擎，解析 `tEXt` 块内的元数据：
* **兼容规范**：
  * V2 规范：解析 Base64 编码的 `chara` 字段；
  * V3 规范（[kwaroran/character-card-spec-v3](https://github.com/kwaroran/character-card-spec-v3)）：解析 `ccv3` 规范的完整结构体（包含 `data.system_prompt`, `data.post_history_instructions`, `data.character_book` 等）。
* **动态宏展开引擎**：
  在 Prompt 组装时，支持实时替换：`{{char}}`（角色名）、`{{user}}`（用户自设昵称）、`{{current_time}}`、`{{current_app}}`（当前前台 App）、`{{battery_level}}` 等环境宏。

### 5.1.2 人格稳定性与抗漂移四大机制（小汐护城河）
将原有小汐代码中的精华抽取为**通用中间件**，适用于任何角色卡：
1. **PHI（Post-History Instructions）强语气重锚**：
   在 Context 构建时，`post_history_instructions` **永远置于对话历史的最尾端、LLM 预测之前**。由于 Transformer 的注意力偏置（Recency Bias），尾部重锚能压制多轮长对话后 LLM 倾向于变成客服腔的本能。
2. **8 轮抗漂移周期重注入（8-Turn Drift Shield）**：
   维护对话轮数计数器。每经历 8 轮交互，自动在请求中注入一份压缩版核心设定与约束清单，对抗注意力衰减。
3. **反 AI 腔过滤器（Humanness Gap Filter）**：
   禁止词汇与句式黑名单（如：“作为一个人工智能模型…”、“我理解您的感受…”、“祝您生活愉快…”）。输出阶段若检测到此类句式，触发本地拦截与自动重写。
4. **采样超参数自适应**：
   针对不同模型端点做参数清洗（如 DeepSeek 强制清洗 `top_p=0` 的报错陷阱，默认使用 Temperature 0.95，Presence Penalty 0.25 维持鲜活度）。

### 5.1.3 双轨记忆系统（Dual-Track Memory）
彻底改造旧有只有“关于用户”的单向记忆库，建立双轨体系：
* **用户轨（Track A - User Profile & Facts）**：
  记录用户的喜好、作息习惯、重要人际关系、工作压力源。支持矛盾记忆时间戳覆盖（如用户说“我换工作了”，旧公司状态标记为 superseded）。
* **自叙轨（Track B - Self-Experiences & Thoughts）**：
  * **自主经历沉淀**：Agent 在后台自主上网阅读科技资讯、社会热点或艺术故事后，提炼为第一人称心得存入 `self_experiences` 表。
  * **未完成念头池（Unspoken Thoughts Pool）**：Agent 在观察用户行为或思考时产生的“想说但现在不适合说”的碎片念头。当下一次交互触发时，优先作为破冰谈资。

## 5.2 获权“视奸”感知中枢（Perception & Context Engine）

感知中枢是让 Agent 拥有“眼睛和耳朵”的关键，按功耗和频率分为四层过滤网：

```
[ 用户使用手机 ]
       │
       ├─ (1) 基础系统广播 ──→ 屏幕亮/灭、充电、电量变化、时间跳变（零功耗）
       │
       ├─ (2) 应用使用统计 ──→ UsageStatsManager 轮询（前台 App 变更事件）
       │
       ├─ (3) 全局通知监听 ──→ NotificationListenerService 捕获第三方通知
       │
       └─ (4) 无障碍树提取 ──→ AccessibilityService 获取当前页面文字摘要
                                         │
                                         ▼
                               【 隐私熔断过滤器 】
                     （检测到密码框 / 银行应用 / 支付界面?）
                                ├── 是 ──→ [ 物理切断，立即清空上下文 ]
                                └── 否 ──→ [ 格式化情境上下文注入工作记忆 ]
```

### 5.2.1 无障碍轻量级读屏（AccessibilityNodeInfo Parser）
* **零 Token 开销**：通过 `AccessibilityService.getRootInActiveWindow()` 递归遍历当前界面的节点树。
* **关键信息剪枝算法**：过滤掉无意义的容器 Layout 节点，仅提取含有 `text`、`contentDescription` 且可点击或聚焦的关键信息，将整个手机屏幕抽象为一篇不超过 300 字的结构化文本快照（Screen Snapshot）。

### 5.2.2 深度多模态感知（MediaProjection 按需截屏）
当用户主动下达复杂指令（如“看看这张图里穿搭好看吗”），或无障碍树返回空（游戏/画布页面）时：
* 触发 `MediaProjection` 捕获单张高清帧；
* 端侧压缩处理（1080P 等比缩放至 720P，降低 Token 与传输耗时）；
* 送入视觉模型（VLM）进行图文理解。

### 5.2.3 绝对隐私隔离防线（Zero-Compromise Privacy）
1. **密码保护硬隔离**：无障碍树节点若命中 `isPassword == true` 或 `InputType.TYPE_TEXT_VARIATION_PASSWORD`，感知引擎立即挂起，不保存任何上下文。
2. **金融/隐私包名物理黑名单**：
   * 包含微信支付/收银台页面、支付宝、各大银行手机 App、1Password/Bitwarden 等密码管理器。
   * 一旦前台包名进入黑名单，全局感知自动降级为“用户正在处理私密事务”，禁止截屏与文字提取。
3. **本地敏感词过滤**：身份证、手机号、信用卡号通过本地 Regex 脱敏后再传入模型。

## 5.3 手机操控与动作执行中枢（Execution & Phone Control Engine）

操控能力采取**“确定性动作优先，多模态推理兜底”**的四级阶梯架构：

| 层级 | 触发机制 | 核心原理 | 适用场景 | 成功率与延迟 |
|---|---|---|---|---|
| **Level 0: Intent 直达** | 结构化动作命中 | Android 原生 Intent / DeepLink | 打开地图导航、拨号、播放歌曲、打开系统设置 | 成功率 ~100%，延迟 <50ms |
| **Level 1: 无障碍模拟** | UI 节点树明确 | `AccessibilityNodeInfo.performAction` 或 `dispatchGesture` 模拟物理点击 | 点击已知文本按钮、输入框文本填充、常规列表滑动 | 成功率 ~95%，延迟 ~150ms |
| **Level 2: VLM 视觉 Grounding** | 未知/复杂非标界面 | 截屏 + AutoGLM/UI-TARS 预测归一化坐标 $(x,y)$，再由 `dispatchGesture` 注入 | 小红书精准搜帖、外卖 App 选规格、游戏界面交互 | 成功率 ~85%，延迟 1.5~3s |
| **Level 3: Shizuku 特权通道** | 高级系统任务 | Shizuku AIDL 调用底层 Shell（`input tap/swipe`, `pm`） | 强制冻结应用、免确认授予权限、全局无死角截屏 | 成功率 ~99%，需要特权授权 |

### 5.3.1 闭环动作执行流（Observe-Plan-Act-Verify）
借鉴 [bytedance/UI-TARS](https://github.com/bytedance/UI-TARS) 的思考机制，在执行多步手机操作时引入“反思环”：
1. **Observe**：获取当前屏幕快照（无障碍树或截图）；
2. **Plan**：大模型输出思维链（Thought）与下一步动作原子指令（Action）；
3. **Act**：通过系统无障碍或 Shizuku 注入动作；
4. **Verify**：等待 500ms 页面过渡动画，抓取新一帧屏幕，与预期状态对比：
   * 状态符合预期 $\rightarrow$ 进入下一步；
   * 状态未变化（如按钮未点中） $\rightarrow$ 微调坐标重试（最多 3 次）；
   * 状态异常（弹出未知弹窗） $\rightarrow$ 规划关闭弹窗动作。
5. **Human-In-The-Loop 强阻断**：遇到“立即付款”、“输入密码”、“确认删除”、“授权转账”等敏感边界，立刻中断执行，弹窗邀请用户亲自操作。

## 5.5 主动性裁决器与自主生活循环（Proactivity & Autonomous Life）

### 5.5.1 告别随机抽签：Agent-Judged Silence 沉默裁决模型
彻底废弃旧代码中 `heartbeat.py` 里的“50% 纯随机抛硬币”逻辑。引入情境感知评估树：

```kotlin
fun evaluateProactivity(context: PhoneContext, persona: PersonaConfig): ProactiveDecision {
    // 1. 硬性规则守门：用户处于全屏横屏游戏、观看视频、通话中 → 绝对静默
    if (context.isImmersiveOrMediaPlaying || context.isInCall) return ProactiveDecision.SILENT
    
    // 2. 频次与作息熔断：距离上次主动发声不足 45 分钟，或深夜无异常行为 → 静默
    if (context.timeSinceLastInteraction < 45.minutes && !context.isEmergency) return ProactiveDecision.SILENT
    
    // 3. 意图价值评分（基于上下文显著度）
    val score = calculateSalienceScore(context) // 熬夜 +40, 收到压力通知 +30, 频繁切换 App 发呆 +20
    if (score < persona.proactivityThreshold) return ProactiveDecision.SILENT
    
    // 4. 交由裁决小模型/轻量规则判断：是弹气泡、做小表情，还是保持陪伴
    return ProactiveDecision.TRIGGER_BUBBLE
}
```

### 5.5.2 自主生活循环（Independent Living Cycle）
为了让 Agent 拥有真实的灵魂，必须解决“素材井单一”的通病：
* **后台轻量巡航（每日 2~3 次）**：在系统充电且连接 Wi-Fi 时，Agent 后台通过轻量 Web Search 抓取特定领域的趣闻（根据角色性格自设兴趣点，如动漫、科技、摄影、美食）。
* **经历内化**：Agent 自动总结一条日记存入 `self_experiences`（如：“今天在网上看到一个很有意思的概念叫‘数字游民’，不知道搭档平时工作压力那么大，会不会也向往这种生活…”）。
* **勾连式表达**：当下次触发主动搭话时，Agent 会采用**“引子 + 勾连”**的自然方式（“刚才看你一直在切应用，是不是写代码卡壳啦？我下午刚好看到一个很搞笑的梗，讲给你听听？”），杜绝生硬的天气播报。

# 七、 质量保障、隐私防线与项目纪律

### 7.1 执行纪律与 TDD 流程
1. **测试先行（Red-Green-Refactor）**：所有逻辑代码编写前，必须先写单元测试并确认红灯，实现后跑绿，严禁无测试直接写业务。
2. **渐进式重构**：每个 Task 聚焦单一模块，代码改动后必须运行全量回归套件。
3. **一个 Task 一个原子 Commit**：规范化 Git Commit 信息（如 `feat(mind): implement STv3 lorebook keyword matching`）。

### 7.2 电池保活与系统稳定性
* **唤醒锁严控**：严禁无限制申请 `PARTIAL_WAKE_LOCK`。后台任务全部交由 Android 原生 `WorkManager`（利用充电 + Wi-Fi 约束调度）。
* **内存预算**：悬浮窗常驻模式下，内存占用严格控制在 **80MB 以下**，避免被系统低内存强杀。

### 7.3 隐私合规与安全防线
* **零上传底线**：除用户自设的大模型 API 接口外，App 内无任何第三方统计 SDK、无任何中心化云服务数据回传。
* **明确授权向导**：所有高权限（无障碍、通知监听、悬浮窗、使用记录）必须在初始引导页以极具诚意的图文形式向用户解释用途，并明确告知“所有数据仅存本地”。
