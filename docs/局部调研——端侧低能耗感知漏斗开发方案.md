## 0. 架构决策与核心工程指标 (KPI)

### 0.1 核心设计哲学
1. **每瓦有效信息增益优先**：摒弃孤立的“百分比过滤率”，以 **$\text{Gain} = \frac{\Delta \text{Confirmed Key Events}}{\Delta \text{Energy (Joules)}}$** 作为全流水线第一优化目标。
2. **少调 L2 即是胜利**：L2 单次推理开销（0.5ms~600ms）比 L1（0.5ms~2ms）高出 1~3 个数量级。L1 的核心任务是阻断 95% 以上无效变动，杜绝 L2 滥用。
3. **合规双轨解耦**：针对 Google Play 2026-01-28 生效的无障碍新政（严禁自主规划与执行），设计合规隔离层，保证业务在国内外生态中弹性部署。
4. **可验证安全物理覆黑**：敏感信息阻断绝不依赖高斯模糊或第三方 App 自觉设防，端侧内存物理覆黑并闭环校验。

### 0.2 工程验收红线

| 维度 | 生产验收指标 (Redline) | 测量环境 / 评估基准 |
| :--- | :--- | :--- |
| **全天待机额外耗电** | $\le 3.5\%$ (满电 24h 伴生常驻) | 典型用户日常交互 4h + 息屏待机 20h（参考 [S31] 梯形积分法） |
| **主线程 Binder 阻断延迟** | $\le 0.1\text{ ms}$ (严格脱钩) | `onAccessibilityEvent` 入队即走，严禁在 Binder 线程遍历树 |
| **L1 级平均判定延迟** | $\le 1.8\text{ ms}$ (小核运行) | 涵盖无交互节点剪枝、Fastbot 状态指纹计算与 AC 自动机匹配 |

## 1. 合规架构与双轨运行模式 (Dual-Track Architecture)

针对 **2026-01-28 生效的 Google Play Accessibility API 政策**及 Android 16 的 `accessibilityDataSensitive` 限制，系统在应用架构层实施动静解耦：

```
                           [ 启动与环境嗅探 (App Launch) ]
                                          │
                  ┌───────────────────────┴───────────────────────┐
                  ▼                                               ▼
      [ Track A: Google Play 合规轨道 ]              [ Track B: 深度感知轨道 (OEM/侧载) ]
      (Distribution: Google Play Store)              (Distribution: 国内应用商店/官网APK)
  ┌──────────────────────────────────────┐       ┌──────────────────────────────────────┐
  │ 1. 禁用 Accessibility 全局服务注册   │       │ 1. 启用 AccessibilityService 漏斗     │
  │ 2. NotificationListenerService (通知)│       │ 2. isAccessibilityTool = false 声明  │
  │ 3. 辅助交互入口 (Assist Interaction) │       │ 3. 严格只读模式：禁止任何 ACTION 注入  │
  │ 4. QuickSettings Tile / 浮窗点击取景 │       │ 4. L0 -> L1 -> L2 全流水线自治运行   │
  └──────────────────────────────────────┘       └──────────────────────────────────────┘
```

*   **Track A（合规伴生模式）**：
    *   服务配置完全移除 `<accessibility-service>` 声明，避免任何 Play Protect 下架风险。
    *   以系统的 `NotificationListenerService` 为主要被动触发源（极低功耗，仅处理通知流）；以 Android 标准的 `VoiceInteractionSession` 或悬浮磁贴由用户显式触发单次屏幕感知（Single-shot capture）。
*   **Track B（深度常驻模式）**：
    *   针对国内市场及私有部署。在 XML 中明确声明 `isAccessibilityTool="false"`。
    *   在服务内部强制实现“**只读隔离（Read-Only Isolation）**”：禁用无障碍节点的 `performAction()` 调用链（编译期通过代码检查切断），在应用说明页提供透明感知日志与安全视频。

## 2. 系统总体架构与线程拓扑 (System Pipeline)

为杜绝任何由于无障碍事件洪泛引发的系统 UI 卡顿（AOSP `AccessibilityInputFilter` 在 60Hz/120Hz 刷新率下若延迟超过 8.3ms 即导致掉帧），感知系统采用**四层无锁管道模型**：

```
  [AOSP Binder 线程]
         │  onAccessibilityEvent(event)
         ▼  (耗时 <0.05ms: 浅拷贝核心字段至 RingBuffer)
┌────────────────────────────────────────────────────────┐
│ L0 环形无锁单生产者单消费者队列 (SPSC RingBuffer, 容量 128)│
└──────────────────────────┬─────────────────────────────┘
                           │ (后台线程消费，无锁唤醒)
                           ▼
┌────────────────────────────────────────────────────────┐
│ WorkerHandlerThread (优先权: THREAD_PRIORITY_BACKGROUND)│
│  ├─ L0: 包名哈希过滤 / 屏幕传感器状态门控                │
│  ├─ L1: 惯性滑动抑制器 (300ms 阻尼窗)                    │
│  ├─ L1: 节点树剪枝 + Fastbot 状态指纹比对                │
│  └─ L1: Aho-Corasick 多模槽位匹配                       │
└──────────────────────────┬─────────────────────────────┘
                           │ (判定 key_info_appeared == true)
                           ▼
┌────────────────────────────────────────────────────────┐
│ PrivacySanitizer (隐私防火墙)                          │
│  ├─ FLAG_SECURE 阻断 / isPassword 节点坐标收集          │
│  └─ 敏感应用 Activity 黑名单阻断                        │
└──────────────────────────┬─────────────────────────────┘
                           │ (安全像素与坐标提取)
                           ▼
┌────────────────────────────────────────────────────────┐
│ L2 Dedicated Inference Worker (独立单线程任务流)        │
│  ├─ HardwareBuffer / GraphicBuffer 零拷贝单帧抽取       │
│  ├─ 物理 Canvas 扩界覆黑 (Solid Blackout 15%)          │
│  ├─ NPU / LiteRT 局部算力推理 (ROI Det / OCR)          │
│  └─ 差分反查自检与外发打包                             │
└────────────────────────────────────────────────────────┘
```

### 2.1 内存生命周期与零拷贝策略
1.  **禁止深度克隆**：AOSP 的 `AccessibilityEvent.obtain(event)` 在高并发下造成严重的 GC 垃圾回收停顿。系统仅抽取结构化元组：`(eventType, packageName, className, eventTime)`，构造对象池复用的轻量 POJO。
2.  **节点回收契约**：调用 `getRootInActiveWindow()` 获得的根节点及其子节点，必须在递归分析完成后立即调用 `recycle()`（针对 Android 13 及以下）或置空（Android 14+），单次 L1 分析驻留内存不超过 200KB。
3.  **GraphicBuffer 共享纹理**：当触发 L2 截屏时，采用 `ImageReader.newInstance(w, h, PixelFormat.RGBA_8888, 2, HardwareBuffer.USAGE_GPU_SAMPLED_IMAGE)`，直接在 Native 层通过 `AHardwareBuffer_lock` 映射指针，禁止将全分辨率整屏拷贝至 JVM 堆内存。

## 3. L0 级：零算力硬过滤设计 (Zero-Compute Hard Filter)

L0 是防御的第一道闸口，执行成本控制在纳焦～微焦级（$<0.05\text{ ms}$）。

### 3.1 静态服务声明配置
严禁在 `res/xml/accessibility_service_config.xml` 中使用宽泛监听：

```xml
<?xml version="1.0" encoding="utf-8"?>
<accessibility-service xmlns:android="http://schemas.android.com/apk/res/android"
    android:description="@string/accessibility_service_description"
    android:accessibilityEventTypes="typeWindowStateChanged|typeWindowContentChanged|typeViewClicked|typeNotificationStateChanged"
    android:accessibilityFeedbackType="feedbackGeneric"
    android:notificationTimeout="150"
    android:accessibilityFlags="flagDefault|flagRetrieveInteractiveWindows"
    android:canRetrieveWindowContent="true"
    android:isAccessibilityTool="false" />
```
*   **`android:notificationTimeout="150"`**：配置 150ms 框架级节流，由 AOSP 框架合并同类高频事件，削减底层 IPC 传输频次。
*   **不设置 `flagIncludeNotImportantViews`**：确保系统底层自动裁撤无辅助价值的冗余布局节点。

### 3.2 传感器与系统状态硬件门控 (`SensorGateKeeper`)
利用系统的低功耗监听器在进程内维持原子状态位，在 Binder 回调入口处实现 $O(1)$ 瞬时短路：

```kotlin
class SensorGateKeeper(context: Context) {
    @Volatile var isScreenInteractive: Boolean = true
    @Volatile var isDeviceInPocket: Boolean = false
    @Volatile var isUserStationary: Boolean = true

    init {
        // 1. 屏幕亮灭屏监听 (广播开销极小)
        val displayManager = context.getSystemService(Context.DISPLAY_SERVICE) as DisplayManager
        displayManager.registerDisplayListener(object : DisplayManager.DisplayListener {
            override fun onDisplayChanged(displayId: Int) {
                val display = displayManager.getDisplay(displayId)
                isScreenInteractive = (display?.state == Display.STATE_ON)
            }
            override fun onDisplayAdded(displayId: Int) {}
            override fun onDisplayRemoved(displayId: Int) {}
        }, null)

        // 2. 接近传感器门控 (口袋模式防误触)
        val sensorManager = context.getSystemService(Context.SENSOR_SERVICE) as SensorManager
        val proximitySensor = sensorManager.getDefaultSensor(Sensor.TYPE_PROXIMITY)
        proximitySensor?.let {
            sensorManager.registerListener(object : SensorEventListener {
                override fun onSensorChanged(event: SensorEvent) {
                    isDeviceInPocket = (event.values[0] < event.sensor.maximumRange)
                }
                override fun onAccuracyChanged(sensor: Sensor?, accuracy: Int) {}
            }, it, SensorManager.SENSOR_DELAY_NORMAL)
        }
    }

    @Inline
    fun shouldFastDrop(): Boolean {
        // 息屏或在口袋中，立即 0 算力丢弃
        return !isScreenInteractive || isDeviceInPocket
    }
}
```

### 3.3 高速包名与类型布隆/哈希查找
在 Native 层或通过预编译的整型哈希集（`FastIntSet`）比对包名与类名：
*   **系统桌面与键盘白名单拦截**：如 `com.android.systemui`（通知栏下拉除外）、输入法键盘（如 `com.sohu.inputmethod.sogou`、`com.google.android.inputmethod.latin`）直接标记为快速丢弃，避免打字输入时每个字符变动均触发全树扫描。

## 4. L1 级：轻量启发式过滤设计 (Lightweight Heuristics)

L1 在后台 WorkerHandlerThread 中运行，单次耗时控制在 $0.5 \sim 2.0\text{ ms}$，彻底消除 95% 的滑动过程态与无意义动画。

### 4.1 惯性滑动抑制器 (Fling Quiescence Damper)
针对列表滑动（`TYPE_VIEW_SCROLLED`），设计基于滑动动量衰减的 Trailing Debounce 状态机：

```kotlin
class FlingQuiescenceDamper(
    private val debounceTimeoutMs: Long = 300L,
    private val onQuiescent: (packageName: String) -> Unit
) {
    private var lastScrollTime = 0L
    private var pendingPackage: String? = null
    private val handler = Handler(Looper.getMainLooper())

    private val checkQuiescentRunnable = Runnable {
        val now = SystemClock.uptimeMillis()
        if (now - lastScrollTime >= debounceTimeoutMs) {
            pendingPackage?.let { onQuiescent(it) }
            pendingPackage = null
        }
    }

    fun onScrollEvent(packageName: String) {
        lastScrollTime = SystemClock.uptimeMillis()
        pendingPackage = packageName
        handler.removeCallbacks(checkQuiescentRunnable)
        // 重新推迟至 300ms 冷却后执行
        handler.postDelayed(checkQuiescentRunnable, debounceTimeoutMs)
    }
}
```

### 4.2 UI 节点树剪枝与 Fastbot 三元组状态指纹
基于字节跳动 Fastbot（AST'20 [S33]）经过 15 亿月活验证的 State 抽象方法，定义状态指纹：
$$\text{StateFingerprint} = \text{MurmurHash3}(\text{ActivityName} \parallel \text{ActionableTypes} \parallel \text{FlattenedLayout})$$

```kotlin
object FastbotStateHasher {
    // 递归剪除不可见节点及无交互排版容器
    fun computeFingerprint(root: AccessibilityNodeInfo?, currentActivity: String): Long {
        if (root == null) return 0L
        var hash = 1125899906842597L // FNV offset basis
        hash = hash xor currentActivity.hashCode().toLong()

        val deque = ArrayDeque<AccessibilityNodeInfo>()
        deque.push(root)

        while (deque.isNotEmpty()) {
            val node = deque.pop()
            
            // 剪枝 1: 对用户不可见节点直接放弃
            if (!node.isVisibleToUser) {
                continue
            }

            val isActionable = node.isClickable || node.isLongClickable || node.isEditable
            val hasText = !node.text.isNullOrEmpty() || !node.contentDescription.isNullOrEmpty()

            // 剪枝 2: 无交互能力且无文本的纯布局容器，仅入栈子节点，不参与指纹计算
            if (isActionable || hasText) {
                val nodeSig = ((node.className?.hashCode() ?: 0) * 31 + 
                               (node.viewIdResourceName?.hashCode() ?: 0)) * 31 + 
                               (node.text?.hashCode() ?: 0)
                hash = (hash xor nodeSig.toLong()) * 1099511628211L
            }

            for (i in 0 until node.childCount) {
                node.getChild(i)?.let { deque.push(it) }
            }
        }
        return hash
    }
}
```

### 4.3 Aho-Corasick 多模模式匹配与三判据与逻辑
端侧不判断整句自然语言含义，仅扫描业务关注的**高价值语义槽位（Slot Anchors）**：
*   **槽位表定义**：
    *   `FINANCE`: `[¥, RMB, 支付, 待支付, 实付, 交易成功, 账单]`
    *   `TRAVEL`: `[登机口, 航班动态, 预计送达, 骑手已接单, 动车, 取票号]`
    *   `SECURITY`: `[验证码, 动态口令, 风险提示, 授权登录]`

```kotlin
class PerceptionGateKeeper(private val acMatcher: AhoCorasickTree) {
    private var lastFingerprint = 0L

    fun evaluateScreenTransition(
        root: AccessibilityNodeInfo?,
        activityName: String,
        event: AccessibilityEvent
    ): Boolean {
        // 判据 1: 系统主动语义信号（第 0 层高置信快速通道）
        if (event.contentChangeTypes and AccessibilityEvent.CONTENT_CHANGE_TYPE_ERROR != 0 ||
            event.eventType == AccessibilityEvent.TYPE_NOTIFICATION_STATE_CHANGED) {
            return true // 快速放行
        }

        // 判据 2: 计算 Fastbot 状态指纹，若页面结构与交互项未发生实质突变，直接阻断
        val currentFingerprint = FastbotStateHasher.computeFingerprint(root, activityName)
        if (currentFingerprint == lastFingerprint) {
            return false // 界面仅微小滚动或无意图变动
        }
        lastFingerprint = currentFingerprint

        // 判据 3: 提取全屏有效文本流，执行 Aho-Corasick 多模式匹配
        val visibleTextBuffer = StringBuilder(1024)
        extractVisibleText(root, visibleTextBuffer)
        val hitKeywords = acMatcher.searchAll(visibleTextBuffer.toString())

        // 实施三判据与逻辑：结构突变 AND 命中关键槽位
        return hitKeywords.isNotEmpty()
    }

    private fun extractVisibleText(node: AccessibilityNodeInfo?, sb: StringBuilder) {
        if (node == null || !node.isVisibleToUser) return
        node.text?.let { sb.append(it).append(' ') }
        node.contentDescription?.let { sb.append(it).append(' ') }
        for (i in 0 until node.childCount) {
            extractVisibleText(node.getChild(i), sb)
        }
    }
}
```

## 5. L2 级：端侧轻量视觉/OCR/NPU 阶梯推理设计 (Edge Perception Engine)

L2 必须是**级联算力阶梯（Cascaded Compute Ladder）**，杜绝一上来就跑 600ms 的整屏大模型。

```
 [L1 审核放行]
      │
      ▼
┌──────────────┐  差异极小 (<1.5%)
│ L2a: 像素差分 ├───────────────────> [ 立即阻断，无硬件推理消耗 (<1ms) ]
└──────┬───────┘
       │ 差异超阈
       ▼
┌──────────────┐  无关键目标
│ L2b: ROI检测 ├───────────────────> [ 终止流水线 (NPU: 0.5ms / CPU: 5ms) ]
└──────┬───────┘
       │ 命中关键目标框 (Bounding Box)
       ▼
┌──────────────┐
│ L2c: 局部OCR ├───────────────────> [ 提取高置信文本，打包上传 (10~25ms) ]
└──────┬───────┘
       │ 遇到复杂未知模态 / 需高维决策
       ▼
┌──────────────┐
│ L2d: 多任务屏 │ (仅限连接充电桩或用户交互显式触发，Snapdragon HTP: 55ms)
└──────────────┘
```

### 5.2 变长 OCR 文本识别的“分桶静态张量（Bucketing）”
由于 NPU 底层 VTCM 静态内存映射机制，动态张量输入会导致算子回退 CPU。针对端侧 PP-OCRv4 识别模型实施分桶规整：

| 桶 ID | 统一输入分辨率 ($C \times H \times W$) | 适用文本场景 | 补齐方案 |
| :--- | :--- | :--- | :--- |
| **Bucket-1** | $3 \times 48 \times 160$ | 短验证码、金额、时间、状态标签 | 保持宽高比，右侧零填充（Zero-padding） |
| **Bucket-2** | $3 \times 48 \times 320$ | 订单号、航班号、普通标题单行 | 保持宽高比，右侧零填充 |
| **Bucket-3** | $3 \times 48 \times 640$ | 长句、对话消息气泡单行 | 保持宽高比，右侧零填充 |

通过分桶，确保 NPU 仅加载 3 套预编译图，实现 $100\%$ 硬件指令驻留，单行文本推理压至 **$1.8\text{ ms} \sim 3.5\text{ ms}$**。

## 6. 边缘隐私遮蔽与可验证安全体系 (Privacy Redaction & Verification)

隐私遮蔽是本系统的不可妥协防线。系统构建**“硬门控前置阻断 + 节点脱敏 + 图像覆黑 + 差分自检”**的闭环。

```
 [屏幕原始画面] ──> [FLAG_SECURE / Android 16 敏感检测] ──> (命中: 硬件直接置黑)
       │
       ▼ (正常画面)
 [无障碍树敏感扫描] ──> isPassword() / PII 正则 ──> 收集敏感坐标集: List<Rect>
       │
       ▼
 [物理像素覆黑 (Solid Blackout)] ──> Canvas.drawRect(Rect + 15% Margin, SolidBlack)
       │
       ▼
 [差分反查自检引擎 (Differential OCR Verification)]
       ├─ 在覆黑外扩区域内执行 3ms 快速文本扫查
       ├─ IF 仍检出字符 -> [ 触发运行时硬熔断 (Panic & Drop Frame) ]
       └─ ELSE -> [ 允许打包外发 ]
```

### 6.1 绝对坐标物理覆黑算法实现
严禁使用高斯模糊或马赛克（防止扩散模型逆向去噪），采用外扩 15% 固体纯黑填充：

```kotlin
object VisualRedactor {
    private val blackPaint = Paint().apply {
        color = Color.BLACK
        style = Paint.Style.FILL
        isAntiAlias = false // 禁用抗锯齿，防止边缘半透明像素泄漏字符边缘
    }

    fun applyRedaction(sourceBitmap: Bitmap, maskRects: List<Rect>): Bitmap {
        val mutableBitmap = if (sourceBitmap.isMutable) sourceBitmap else sourceBitmap.copy(Bitmap.Config.ARGB_8888, true)
        val canvas = Canvas(mutableBitmap)

        for (rect in maskRects) {
            // 计算 15% 外扩容差，严防亚像素渲染、阴影及斜体字泄漏
            val dx = (rect.width() * 0.15f).toInt().coerceAtLeast(4)
            val dy = (rect.height() * 0.15f).toInt().coerceAtLeast(4)
            
            val inflatedRect = Rect(
                (rect.left - dx).coerceAtLeast(0),
                (rect.top - dy).coerceAtLeast(0),
                (rect.right + dx).coerceAtMost(sourceBitmap.width),
                (rect.bottom + dy).coerceAtMost(sourceBitmap.height)
            )
            canvas.drawRect(inflatedRect, blackPaint)
        }
        return mutableBitmap
    }
}
```

### 6.2 差分双轨验证与运行时熔断 (Runtime Differential Verification)
在物理覆黑后，由轻量检测算子在原坐标 ROI 进行复核：

```kotlin
class PrivacyFirewall(private val lightTextDetector: LightTextDetector) {
    fun verifyAndEmit(bitmap: Bitmap, sanitizedRects: List<Rect>): Boolean {
        for (rect in sanitizedRects) {
            // 提取被遮蔽区域的像素块
            val roiBitmap = Bitmap.createBitmap(bitmap, rect.left, rect.top, rect.width(), rect.height())
            // 运行超高速二值化文本探测 (耗时 <2ms)
            val hasResidualText = lightTextDetector.hasTextFeatures(roiBitmap)
            roiBitmap.recycle()

            if (hasResidualText) {
                // 触发安全熔断：发生未预期的坐标偏移或遮蔽失败，坚决销毁数据
                bitmap.recycle()
                AuditLogger.logSecurityViolation(rect, "TEXT_RESIDUE_DETECTED")
                return false // 丢弃该帧，禁止上传
            }
        }
        return true
    }
}
```

### 7.1 软件法自动化能耗测量引擎 (`BatteryProfiler`)
严格遵循 [arXiv:2603.26603 S31] 方法学，使用 `BatteryManager` 实现高精度微焦耳积分：

```kotlin
class BatteryProfiler(private val context: Context) {
    private val batteryManager = context.getSystemService(Context.BATTERY_SERVICE) as BatteryManager
    private val sampleIntervalMs = 100L
    private val samples = mutableListOf<PowerSample>()
    private var isRunning = false
    private val handler = Handler(Looper.getMainLooper())

    data class PowerSample(val timestampNs: Long, val voltageMv: Long, val currentUa: Long)

    private val samplerRunnable = object : Runnable {
        override fun run() {
            if (!isRunning) return
            val now = SystemClock.elapsedRealtimeNanos()
            val voltage = batteryManager.getIntProperty(BatteryManager.BATTERY_PROPERTY_VOLTAGE).toLong()
            val currentNow = batteryManager.getIntProperty(BatteryManager.BATTERY_PROPERTY_CURRENT_NOW).toLong() // 负值代表放电电流 (uA)

            samples.add(PowerSample(now, voltage, abs(currentNow)))
            handler.postDelayed(this, sampleIntervalMs)
        }
    }

    fun startProfiling() {
        samples.clear()
        isRunning = true
        handler.post(samplerRunnable)
    }

    // 梯形积分计算实际消耗能量（焦耳 Joules）
    fun stopAndIntegrate(baselinePowerMw: Double): Double {
        isRunning = false
        handler.removeCallbacks(samplerRunnable)

        if (samples.size < 2) return 0.0
        var totalEnergyJoules = 0.0

        for (i in 1 until samples.size) {
            val sPrev = samples[i - 1]
            val sCurr = samples[i]

            val dtSeconds = (sCurr.timestampNs - sPrev.timestampNs) / 1_000_000_000.0
            // 计算当前瞬时功率 (mW) = V (mV) * I (uA) / 10^6
            val powerPrevMw = (sPrev.voltageMv * sPrev.currentUa) / 1_000_000.0
            val powerCurrMw = (sCurr.voltageMv * sCurr.currentUa) / 1_000_000.0

            // 扣除空载基线功率
            val netPowerPrev = (powerPrevMw - baselinePowerMw).coerceAtLeast(0.0)
            val netPowerCurr = (powerCurrMw - baselinePowerMw).coerceAtLeast(0.0)

            // 梯形法数值积分: E = (P1 + P2)/2 * dt (mJ -> Joules: /1000)
            val stepEnergyMilliJoules = (netPowerPrev + netPowerCurr) / 2.0 * dtSeconds
            totalEnergyJoules += (stepEnergyMilliJoules / 1000.0)
        }
        return totalEnergyJoules
    }
}
```

## 9. 风险矩阵与降级应急预案 (Risk Management)

| 风险场景 | 影响级别 | 触发条件 | 自动降级与应急对策 |
| :--- | :--- | :--- | :--- |
| **AOSP 框架版本更新导致 API 屏蔽** | 严重 | 设备升级 Android 16/17，非特权无障碍彻底读不到特定节点 | **动态感知降级**：检测到目标节点不可读时，自动唤醒单帧截屏（`takeScreenshotOfWindow`）进入视觉差分模式；若受 `FLAG_SECURE` 保护则彻底静默，记录审计日志。 |
| **第三方 App 采用自绘引擎 (Flutter/Unity)** | 高 | 无障碍树仅暴露单个根节点或完全为空 | **按需视觉突变探测**：L1 判定节点数为 1 且属于自绘类（如 `io.flutter.embedding.android.FlutterView`），启动 L2a 像素差分采样（频率压至 1 次/秒），严防高频轮询。 |
| **NPU 驱动崩溃或模型加载失败** | 中 | 厂商定制 ROM 破坏 Hexagon DSP 动态库链接 | **自动回退熔断机制**：JNI 层捕获 `OrtException`，自动将加速器状态降级为 `LiteRT-GPU` 或 `XNNPACK-CPU`，同时将最大推理频率降为原来的 25%，防止 CPU 发热。 |
| **系统处于极端低电量模式** | 中 | 系统电量 $<15\%$ 或触发省电模式广播 | **感知完全休眠**：挂起所有 L2 视觉与 L1 动态扫描，仅保留通知监听（`NotificationListenerService`），直到充电状态恢复。 |

## 10. 方案总结与落地交底

本方案彻底告别了“盲目套用大模型全屏看图”的低效暴力模式。通过**把好 L0 零算力硬门控、压实 L1 拓扑结构去重、精细化 L2 级联微算力、筑牢物理覆黑安全墙**，将原本无节制的移动端多模态感知流转化为**确定、低耗、可测、安全**的受控工程流水线。配合配套研发的能耗自测套件，使开发团队每一阶段的重构均具备实测物理指标支撑，确保常驻伴生 Agent 在全天候运行中达成“润物细无声”的用户体验。
