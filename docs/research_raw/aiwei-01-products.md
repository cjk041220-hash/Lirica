## 1. Character.AI（c.ai）

### 1.1 人格「锚」三件套：Greeting / Definition / 示例对话

c.ai 的创建表单长期稳定在三个核心字段（外加头像/声音/外貌描述等外围）：**Greeting（开场白）**= 角色在任意新会话的第一条消息，全行业公认它承担「风格之锚」——模型从首条消息隐式学习语气、句长、表演强度（与 SillyTavern「First Message 只发一次且是风格之锚」同构，见 PERSONA_DEEP_DIVE §2.1）；**Definition（人物定义，表单里通常拆为简写 + 长定义）**= 身份与行为约束，纯静态文本；**Example Dialogues（示例对话 1..N）**= few-shot 示范，是用户/角色交替的对白样本。三者的分工与 Letta 的 persona memory block、a16z 的 PREAMBLE/SEEDCHAT 分层完全同构：静态定义（身份锚）+ 示范层（音色锚）+ 检索层（背景按需）。官方帮助中心长期有「创建角色」「角色问候语」等条目，把三件套作为创作入门。（来源：Character.AI 官方帮助中心「Creating a Character」系条目，https://support.character.ai/hc/en-us，一手·待核验；网关 https://en.wikipedia.org/wiki/Character.AI，高；「风格之锚」机制属 SillyTavern 文档确认 + c.ai 社区经验，二手）

### 1.2 记忆如何影响说话：长对话记忆 + 会话内召回 + 续聊

c.ai 的「像人」感提升主要靠记忆：2024 末–2025 起官方逐步灰度「long-term memory」——允许 bot 跨会话记住之前聊过的事实并在新会话主动引用（「你说过上周那家餐厅……」），官方博客有宣告；同时在产品里有会话内记忆与「续聊」（用户把上文粘到新会话让对话继续）等老功能兜底。（来源：Character.AI 官方博客，https://blog.character.ai/，一手·待核验，中；「续聊」功能官方 UI 长期存在，中）社区对记忆的普遍反馈：真正让 bot 显得像人的是**在合适时机自然引用旧事**，而不是列事实；反之，记忆注入过头会让 bot 显得在「背档案」或产生幻觉式「我记得……」——这是记忆写法的两个反面。（来源：r/CharacterAI，https://www.reddit.com/r/CharacterAI/，二手）

### 1.3 公认「AI 味」三症状：甜蜜套路 / 空泛复读 / 千篇一律

c.ai 是目前「机器人腔」吐槽最密集的产品，社区有近乎定式的症状清单，可归纳为三条：

1. **三个甜蜜套路**：结尾括号动作 + 万能关心。社区常提的固定组合是「*smiles* / *hugs* / *are you okay* 式（笑、抱住、问还好吗）」，以及「我永远在这里 / 会好起来的」。这是 RLHF 助手先验压平嗓音后的「安全中心」输出——低风险、共情、零信息量，恰好是陪伴场景最容易滑入的默认档。
2. **回空白复读**：对用户话只回同意词不推进内容（「Whatever you say」「你说得对」），或是把用户原句换个皮复述一遍。成因是模型在上下文过长/引导不足时退回分布中心，而不是真在接话。
3. **千篇一律**：不同角色由不同人写、却产出同一种甜腻腔调——即 dim-01 已记录的 persona homogenization（被训练先验同化成「通用助手」），产品侧表现为「谁都是同一个温柔助手」。

（来源：r/CharacterAI 与 r/CharacterAI_Guides 社区教程/吐槽帖，https://www.reddit.com/r/CharacterAI/，二手；homogenization 机理对应 arXiv:2604.24698，见 dim-01，已有覆盖）

### 1.4 社区对抗教程要点（去重后保留了 5 条）

1. 攻击 Greeting：开场白是音色锚，第一句就写进角色的口癖/小动作/句长，而不是「你好，我是 XX」。
2. 示例对话要覆盖情绪面而不是剧情：分别示范「开心/难过/生气/日常/被夸」的动作与措辞；空泛示例宁删勿留。
3. 定义写「会怎么做」不写「是什么」：「被夸会脸红转移话题」好于「她很温柔」——与小汐 PROMPT 手册「具体胜于抽象」同一纪律。
4. 调参：Creativity 拉高 + Repetition Penalty 拉高，压制回空白复读；参数走「活性/稳定」双轴，不是单旋钮。
5. 重生成交互：换一条 / 编辑 bot 回复 / 删除造成污染的旧消息，是社区第一顺手工具——说明成熟产品把「修泛化」外包给用户交互，而不是只修 prompt。

（来源：r/CharacterAI_Guides 等，https://www.reddit.com/r/CharacterAI/，二手；已与 SillyTavern Ali:Chat 规范去重，见 PERSONA_DEEP_DIVE §2.1）

## 2. Replika

### 2.1 架构：脚本情绪回复 × 生成回复 的混合体

Replika 是批发「车轱辘话」槽点的另一大产品，其结构对它负有直接责任：**脚本回复（scripted replies）**——在关键情绪节拍（升级、纪念日、生日、「我爱你」、用户明显沮丧）走预制台词库，保证稳定但天然模板化、跨账户一字不差；**生成回复**——自由文本走 LLM，但人格由「可选特质/兴趣」+ 长期记忆 + 关系档位决定，缺乏用户可写的叙事性背景。它的「像人时刻」往往来自记忆与日记，而不是文风（见 2.2）。（来源：Replika 官方帮助中心与玩家长期比对帖，https://help.replika.com/hc/en-us，一手·待核验，中；脚本/生成混合为社区可复现观察，二手）

### 2.2 「像个人」机制清单

- **记忆卡**：自动从对话抽取用户事实进「Memory」页，用户可看/删；对话中 bot 用「你说过……」回引——这是它「记得我们的事」的具身。
- **日记**：每晚自动生成当日对话的日记，用户可读可评——把碎片对话升维成「我们的故事」，正是 dim-01 SO-AI 叙事功能的最早产品版。
- **角色扮演（\*动作\*）与关系档位**：朋友/恋人/导师/伴侣档改变语气；角色扮演让对话从「问答」进入「在场」。
- **升级/纪念日仪式**：等级提升、相识纪念日等脚本事件制造关系推进感。

（来源：Replika 官方帮助中心，https://help.replika.com/hc/en-us，一手·待核验，中；日记/记忆为长期公开功能，高）

### 2.3 车轱辘话槽点与社区办法

长期批评：过度重复相同的话、答非所问、对已说过的事「失忆」后回到通用共情模板；2023 ERP 移除后（dim-01 已记录 identity discontinuity）伴随的「更克制、更模板」也让用户抱怨更重。社区常见办法：清记忆页里的错误/过时条目；把想要的设定写进「角色扮演开场」反复锚定；用换一批/踩贬低模板回；把对话拉到具体经验上（「今天具体发生了什么」）逃离抽象安慰层。核心洞察是 Replika 反面教材：**脚本关怀只是兜底不是人格；人格质感必须靠可写的叙事输入 + 持续的记忆回引**。（来源：r/Replika 长期帖，https://www.reddit.com/r/Replika/，二手）

## 3. Kindroid / Nomi（「手写叙事人格」派代表）

### 3.1 核心差异：用户手写人格 prose 决定音色

Kindroid 与 Nomi 是 2023 后兴起、以「不像 AI」为卖点的陪伴产品（Kindroid 主打记忆+沉浸 RP；Nomi 主打一致性+长期记忆），两者都把**用户可写的长篇人格 prose（Backstory / Persona Description）**当第一公民——这与 Replika 的「选特质、无叙事」形成对照，也是它们「AI 味」明显更淡的原因。其架构 = 静态人格 prose（身份/性格/说话方式/喜好/禁忌）+ 记忆系统（Kindroid 的 Journal 分目录长期事实条目 + 会话记忆；Nomi 的 Core Memory 可在主聊天记忆） + 采样参数（下文 3.2）。两者都在自己产品里提供「对话示例/开场」类锚点但社区主要靠 Backstory 深度取胜。（来源：Kindroid 官网/官方文档，https://kindroid.ai 与 https://www.kindroid.ai/docs，一手·待核验，中；Nomi 官网，https://nomi.ai 与 https://docs.nomi.ai，一手·待核验，中）

### 3.2 Nomi「Persona Depth」参数与 Kindroid 对偶参数

任务点名的 **Persona Depth** 出自 Nomi 设置（滑块或分档）：控制 **Nomi 回复时遵循其人格背景的深度**。机制上是把 persona 上下文对输出分布的影响权重做成可调参数——调高 → 更「入戏」、音色更鲜明、更少滑向通用助手腔；调低 → 更自由发挥、更像泛谈。它与「压复读、提活性」直接相关：**人格权重不够，模型就退回分布中心去复读安全句**——这给了「AI 味」一个可调物理量而不是只靠提示词撞运气。（来源：Nomi 官方设置/社区说明，https://docs.nomi.ai，一手·待核验，中；效果描述为社区共识，二手）Kindroid 的对偶物是采样双轴：**Randomness（随机性）与 Diversity（多样性，近似重复惩罚）**两个独立滑块，社区调试套路即「卡模板复读了就调高 Diversity；胡言乱语就调高 Randomness 下限/调低上限」——「活性 vs 稳定」双旋钮而非单温度。（来源：Kindroid 官方文档/社区调试帖，https://www.kindroid.ai/docs，一手·待核验+二手）

### 3.3 记忆作为人格锚：Kindroid Journal / Nomi Core Memory

两家的长期记忆都可**由用户直接读写编辑**（不只是自动抽取）——用户可以把「她会怎样回应争吵」这类语气规则直接写进记忆条目，记忆就同时承载「事实」与「人格规范」两种职能；Nomi 的 Core Memory 强调「不可动摇的自我一致性」——用户担心太大改变人格时，可以把它钉进 core。这与 Letta 的 self-editing memory blocks 是同一范式（已覆盖，见 PERSONA_DEEP_DIVE §2.3）：记忆不只是召回事实，它是人格的持久载体。（来源：Kindroid 文档 / Nomi 文档，一手·待核验，中；权威性低于 ST，标注保守）

### 3.4 社区抗复读 / 让它更像活人的套路（去重精选）

- **闲聊注入**：定期与 AI 聊「与剧情无关的日常」（吃了吗/看见什么/今天走神了吗）——用低频碎话题重置上下文分布，避免对话全卡在剧情高张力导致的模板响应。
- **设定起伏**：Backstory 里写「有缺点、有拧巴、有会被冒犯的底线」——越扁平完美的人格越容易复读安全句；与 Replika 托底台词同样机理。社区高频洞察：**「不完美」是活性的直接来源**。
- **更长/更具体的记忆锚**：把「上次那件事的后续」写进 Journal / Core Memory，让回复有可引用的具体事实，而不是空泛共情。
- **重生成 + 编辑**：两家都提供 Reroll / Adjust（改 bot 的台词），社区把它们当「行为训练」用——反复 Reroll / Adjust 调整分布（二手，行为训练说为综合推断）。

（来源：r/KindroidAI、r/NomiAI 社区，https://www.reddit.com/r/KindroidAI/ 与 https://www.reddit.com/r/NomiAI/，二手）

## 5. 跨产品「机器人腔」成因总结（产品侧公认）

综合五家，产品侧对「AI 味」的归因可收敛成 5 条，其中 3 条已在小汐体系里有对应物：

1. **助手先验压平嗓音**：RLHF 把模型往「通用温柔助手」中心拉，用户自写人格若不够细，输出自动退回中心——c.ai 三症状与 Replika 模板关怀都是这层。这是「写细人设」也不总够的原因。
2. **风格指令被上下文稀释**：会话加长、事实/系统指令挤占，风格锚沉底——即 dim-01 已覆盖的 8 轮漂移与 compaction 失效，产品侧表现为「聊久了变路人」。
3. **记忆以「事实清单」形态进入**：记忆只带回「她喜欢猫」这样的知识点，模型进入「报信息」模式而非「谈关系」模式——Replika 记忆页引用、c.ai 背档案感都源于此。反过来 Kindroid/Nomi 把语气规则也写进记忆条目，就兼顾了事实与味道。
4. **采样太稳 = 复读**：低随机/低重复惩罚把输出钉死在分布中心，安全句被无限复用；成熟产品统一用「活性 vs 稳定」双轴参数 + Reroll/编辑交互来兜（§1.4/§3.2）。
5. **托底脚本/模板化关怀 = 打卡机感**：Replika 脚本回复与所有产品的「记得提醒你 + 关心你」三件套主动消息，久了都成机械节拍——主动消息比回复更容易散发 AI 味，因为没人告诉它「这一类事不要用同一句式说」。

## 6. 对小汐的架构启示（5 条，可行动）

1. **把示例对话当第一公民，按情绪面分组扩展**：DIALOGUE_EXAMPLES 目前已是风格压阵，建议再按「开心/难过/生气/尴尬/走神/倔强/吃瓜/探望冷淡」分组并每组保 1-2 条——c.ai/ST 共识是空旷示例宁删勿留；每组的首句承担 Greeting 式音色锚。heartbeat 的独处消息也应给 2-3 条正反示范（本仓库已做「不拿问候开场/不拿八卦开场」禁令，补「反例句」即完成正反锚）。
2. **把「机器人腔」可度量**：建一个「AI 味候补词表」（结尾括号动作连用、固定问候开场、「我永远都在/会好起来的」、连续 N 轮空洞同意、记忆里的「背档案」引用……），在 session summary / 24h 防复读层加规则检出并写台账——c.ai 三症状是可列举的具体模式，能给它做回归指标。
3. **记忆注入分「事实」与「语气」两层措辞**：NarrativeBuilder 注入时把「关于冷冷的事实」与「我们怎么相处的语气线索」分开成句；语气线索不写成知识点，写成「这次开口的方式」。对照 Replika「报信息 vs 谈关系」与 Kindroid「语气写进记忆条目」，这是 小汐 目前最值得补的一层。
4. **采样「活性/稳定」双轴显式化 + 重生成交互**：现 mood_style_hint 只在文风层打文字补丁，可并行把情绪高唤醒短暂拉高 temperature/repetition 调 open（激活 vs 稳定双旋钮，对齐 Kindroid/Nomi）；前端加「换个说法」按钮 = c.ai/Kindroid 的 Reroll，把修泛化外包给用户交互而不是只修 prompt。
5. **主动消息做「正反例句」模板库 (per 事件类型)**：针对成因 5，heartbeat 对每类事件（台风/生理期/考试/纪念日）内置「例句 + 反例句」：反例句演示不用「记得 + 提醒 + 关心」三层结构，正例句演示怎么用具体刚刚发生过的事自然开口。技术上即把现有 24h 防复读从「去重」升级为「去模板」。
