# 体检报告——Lirica 产品与工程双视角系统检查

> **日期**：2026-09-29 · **检查基线**：master @ 537c606（592 项单测，JVM/Robolectric 口径）
> **检查方式**：严格只读。架构耦合 / 端到端连通性 / 代码质量三路并行探查 + 关键断点逐一回源码亲验。
> **口径声明**：本文全部结论为 JVM 静态与单测分析，真机行为不在本报告验证范围内（见 P0）。

---

## 〇、总体结论

**架构是最值钱的部分，这条判断在 09-29 依然成立且更扎实了**：感知→裁决→表现的单向分层、协程纪律、隐私物理熔断、592 项单测基线，都高于同类个人项目平均水准。批次 1~3 + 2.5 的执行质量总体良好。

但本轮检查发现 **3 处"承诺了却没送到用户眼前"的体验断层**（诚实坦白、情境感知、向量记忆在主聊天全部断链或旁路），以及 **2 处夜间无人值守链路的可观测性黑洞**（Worker 静默重试 + 日志门面被大面积绕过）。另有一处文档反向失实与看板记录断档。

## 一、产品经理视角

### 1.1 定位与架构合理性：✅ 成立

PRD v2.0（09-27 俊凯逐项拍板）的 D1~D24 决策链完整，"共用一台手机的邻居"定位与三大能力阶梯（同屏共感 60% / 自主漫游 30% / 轻量协助 10%）清晰。D16 砍生活工具、D15 语音暂缓、D13 不走云端 VLM——**做减法的纪律执行到位**（README:41 已同步、tracker 停止新增 M3.6 字样）。

### 1.2 端到端体验断点（按用户可感知程度排序）

| # | 断点 | 用户视角后果 | 证据 |
|---|---|---|---|
| 1 | **D5 诚实坦白只完成 2/3** | 她操作失败时，用户看到的仍是干巴巴的"点击操作失败: xxx"技术原因；"那个按钮今天跟我捉迷藏"式的人设化坦白**永远不会出现** | 生成与字段齐备：`HonestNarrator.kt` → `SelfHealingWatchdog.kt:142` → `HelixGuiCoordinator.kt:138-139` 等十余处赋值；但 `NativeToolAgent.kt:371-377/407-413` 失败分支只拼 `result.reason` 丢弃 `honestNarrative`；`overlay/` 与 `ui/` 目录对该字段 **0 消费**（grep 全仓库证实） |
| 2 | **主聊天感知不到"共用一台手机"** | 定位说"邻居共住"，但主聊天 prompt 里没有前台应用、电量、屏幕状态——她聊天时是"盲"的，只有悬浮窗主动搭话那一刻才"看得见" | `ChatViewModel.kt:275-286` 调 PhiMiddleware 时 currentTime/currentApp/batteryLevel 传空串；`ChatViewModel.kt:198-205` 调 `assembleMapBasedContext` 不传 `perceptionSnapshot`（Level 4 即时情境槽空转，`MapBasedPromptAssembler.kt:115-121`） |
| 3 | **向量混合检索被主聊天旁路** | 批次 2.5 苦心落地的语义检索（bge-small-zh + ONNX + 混合重排）只在悬浮窗快捷会话生效；主聊天每轮仍走纯关键词 bigram 召回——"周董→周杰伦"这类语义召回在主场景失效 | `ChatViewModel.kt:174` 先调 `recallUserMemories` 再作为 `preRecalledUserMemories` 传入（:202）；`DualTrackMemoryManager.kt:182-183` 的 `?: retrieve()` 被短路 |
| 4 | 主动性负反馈回路缺一环 | 用户无视破冰气泡后系统学不到"这类话少说"（IGNORED 反馈无触发点） | `OverlayExpandViewModel.kt:183-194` 的 `onIcebreakerIgnored` 全 UI 无调用；`IcebreakerBubble.kt:45-51` 无超时隐退回调 |
| 5 | L3 轻通知档位是空壳 | 三档裁决实际只有两档在跑 | `ProactiveBubbleCoordinator.kt:27` 定义、Impl 从不返回；`OverlayExpandViewModel.kt:101-103` 分支空 |

### 1.3 现阶段缺失的核心能力（对照 PRD 承诺）

1. **M4.0 真机冒烟（D20 拍板"本周启动"）**：本周（09-27~10-03）还剩 4 天。全部 592 项单测是 JVM 口径，`DefaultSecureKeyStore` 的 AndroidKeyStore 硬件路径、悬浮窗、无障碍、SSE 流式在真机上**一次都没跑过**。批次 4/5 的所有验收都压在这块未验证地基上。
2. **批次 4 B 站漫游闭环 / 批次 5 agency 接线**：产品差异化主线（D24 三件套，"她第一次动"）尚未开跑，仍停留在 PRD §6。
3. **BYOK token 用量计量 + 日预算告警**（PRD §5 网关行）：未实现，长跑漫游场景下无成本护栏。
4. **人格浓度**（09-25 遗留，待俊凯定夺）：`PhiMiddleware.kt:349-367` 默认人设仍是抽象形容词堆砌（"细腻敏锐""完整灵魂"），无具体意象锚点（爱好、习惯、口头禅、与用户的具体共同经历）。A（补新世界观）/ B（定位通用底座）/ C（延后）三案仍待拍板。

### 1.4 体验短板（低危但值得记账）

- 导航用 `remember { mutableStateOf }`（`MainActivity.kt:135`）：旋转/进程恢复后从设置页弹回聊天页；
- Settings/Onboarding 绕过 ViewModel 直接写仓储（`SettingsScreen.kt:256-259`、`OnboardingScreen.kt:243`）；
- 悬浮窗 `setContent {}` 内联 128 行五种形态编排 + `?: remember` 条件可组合写法（`CompanionOverlayService.kt:240-255`），状态在 vm 空非空切换时会重建。

## 二、开发工程师视角

### 2.1 架构与耦合

**正面（实测确认，非转述）**：
- perception → proactivity 零反向依赖，分层意图干净；
- 主源码 `GlobalScope` / `runBlocking` / `Thread.sleep` **零命中**；`appScope = SupervisorJob + Dispatchers.IO`（`XiaoxiApplication.kt:75-80`）取舍有注释；
- Compose 屏幕文件基本不碰业务；`CompanionOverlayService.onDestroy` 生命周期收尾完整（:459-472）。

**债务（按危害排序）**：

| # | 问题 | 证据 | 危害 |
|---|---|---|---|
| 1 | **database ↔ persona 双向 import 环** | `DualTrackMemoryManager.kt:9-12` import PhiMiddleware/MapBasedPromptAssembler 并内嵌 prompt 装配（:174-202）；`MapBasedPromptAssembler.kt:3-8` 反向 import 4 个 entity | DB 层不再贫血，改 persona 签名会连环炸记忆层 |

### 2.2 连通性与接口对接

四大链路（聊天 / 主动性 / 记忆 / 梦固化）**主体闭环**：工具调用 5 轮迭代回填（`ChatViewModel.kt:328-356`）、BYOK 双协议 + 401/402/429 中文归因 + 指数退避（`XiaoxiLlmGateway.kt:78-161`）、三档裁决 + INNER_THOUGHT_ONLY 落库与召回消费（`UnspokenThoughtManager.kt:44-50` → `ChatViewModel.kt:418-420`）、WorkManager 24h 入梦产物五表落库且全有消费者——这些**都是真接线，不是纸面架构**。Manifest 六项权限声明与实现一一对上，无僵尸组件。

断点集中在 1.2 表的 #1/#3/#4/#5，此处不重复。唯一补充：主源码 TODO/FIXME/"未接线" **0 命中**——断链全是"隐性断"（字段传了没人接），比显式 TODO 更难发现，本报告已逐一标出。
