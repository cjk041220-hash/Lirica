## 一、系统演进脉络与 SOTA 理论调研

Lirica 经历了从单一网页端陪伴玩具（“小汐 / sonetto”）向**全功能 Android 原生伴生体（Lirica / Project Aether）**的彻底转型。为了在第四轮重构中建立不可替代的壁垒，本方案对 2024~2026 年学术界与开源业界的 SOTA 体系进行系统化解构与借鉴：

### 1.1 认知科学与伴生 Agent 前沿演进
- **ALMA 三层情感动力学 (Gebhard 2005)**：人类情感具有三层时间尺度：Emotion（秒～分级，瞬时情绪） -> Mood（小时～天级，心境状态） -> Personality（年级，人格底色）。SOTA 开源实践（如溪语 AI `xiyu-ai`）验证了：脱离用户刺激时，心境必须具备向基线 E0 惯性衰减的阻尼特性；更重要的是，情绪必须受认知评价（OCC Theory）驱动，而非纯随机游走。
- **CHI 2025 前沿：Inner Thoughts（内心独白理论）**：多方伴生交互的实证研究表明：单纯依据对话历史匹配“下一个说话人”是无效的，伴生体必须具备内隐念头生成机制（Inner Monologue）。AI 伴生体应该像人类一样：先产生内隐想法，经过自我审查与动机评估，再决定是否外显表达。嘴上说的话与内心想法的反差（Dramatic Tension）是拟人高级感的核心来源。

### 1.2 记忆架构与睡眠巩固机制 (Episodic-to-Semantic Consolidation)
- **Tulving 记忆双重编码与海马体睡眠重放 (Stickgold 2005)**：人类记忆分为情境记忆（Episodic Memory，带时空标签的具身体验）与语义记忆（Semantic Memory，泛化的常识与认知信念）。白天发生的无数琐碎感知，人类大脑不会全部无脑存盘，而是在夜间慢波睡眠阶段（NREM SWS）通过海马体向大脑皮层的反向神经重放（Replay），完成冲突消解、抽象概括、时序压缩并剔除冗余。
- **开源标杆对比（Mem0 / Letta / TencentDB-Agent-Memory）**：Letta (MemGPT) 提出了分层内存（Core / Archival / Recall）；HippoRAG (NeurIPS 2024) 引入图谱神经联想解决长上下文召回遗漏。Lirica 的端侧裁决：移动设备严苛的能耗与网络约束，排除了将所有屏幕原始日志上传云端图数据库的方案。必须走“端侧低功耗聚合切片 -> 夜间闲时/充电时 WorkManager 驱动梦境提炼 -> 固化为语义经历（Track B）”的本地闭环路线。

### 1.3 可中断性与主动性动力学 (Cost of Interruption & Inner Thoughts)
- **Horvitz 期望打扰代价模型与 Calm Technology**：Mark Weiser 的平静技术哲学（Calm Technology）指出：技术应在人类注意力的边缘（Periphery）常态运行，仅在必要时移入中心（Center）。Horvitz 提出的期望决策模型：Utility = P(User Needs Info) * Benefit - Cost_int(t)。伴生体是否开口，取决于其内在动机增益是否超过当前的环境打扰代价 Cost_int(t)。在用户打游戏、开会、高专注度工作时，打扰代价趋近无穷大；在屏幕刚解锁（SCREEN_UNLOCK）或应用切换天然断点（APP_SWITCH）时，打扰代价降至最低。

### 1.4 移动端 GUI 自动化与混合接地 (Hybrid Grounding)
- **Mobile-Agent v2 / UI-TARS / AndroidWorld 最佳实践**：纯多模态视觉模型（VLM）存在延迟高（单步 >2.5s）、Token 开销大、移动网络不可靠的问题；纯无障碍树在面对游戏、自绘 Canvas、Flutter 等复杂界面时存在“盲区”。SOTA 的工业级解决方案是混合接地（Hybrid Grounding）：优先使用无障碍树进行纳秒级精确查找 -> 未命中时平滑回退至端侧离线 ML Kit OCR 视觉定位 -> 结合动作分块宏（Action Chunking），兼顾极速与鲁棒性。

### 1.5 权限分级与物理安全绝缘 (Waterfall Permission Gate)
- **DeepSeek Harness (DSH) 权限哲学**：DSH 确立了“模式借用、依赖隔离”与 Waterfall 权限门原则：只读查询自动放行，敏感写操作显式弹窗审批，不可逆破坏动作绝对物理熔断。结合 Android 平台的特殊性，必须落实“安全物理层”（PRD D6/D8）：涉及银行支付、即时通讯代发、系统锁屏密码的区域，由代码常量在底层写死断流，坚决不向模型规划暴露任何绕过途径。

## 二、Lirica 代码现状与四大体验断层深度诊断

对照当前仓库（150 个 Kotlin 源码，597 项测试），系统骨架高度健全，但在端到端体验上存在 4 处深层次断裂：

1. **断层一：相处痕迹“阅后即焚”，感知与记忆固化断裂**：PerceptionPipeline 汇聚了无障碍读屏、通知、前台应用时长与硬件状态，但感知数据生命周期仅存在于内存 StateFlow。如果用户一下午都在自习或戴耳机听歌，只要没主动点开聊天框，这些陪伴细节在当晚便无痕消失。夜间运行的 SubconsciousDreamCoordinator 只能处理聊天产生的 UserMemoryEntity，没有感知原料可供消化。
2. **断层二：开环记忆 (Open Loops) 追踪与关怀闭环缺位**：缺乏通用的未决事务追踪状态机。当用户说“明天下午 2 点有场重要面试”，系统仅记为静态事实，到了时间前不会产生关怀念头，事后不会询问结果，无法形成追踪闭环。
3. **断层三：具身生活叙事单薄，通用 Preset 人设棱角偏平**：HardwareEnvironmentWatcher 监听电池电量、充电状态、耳机插拔，但宏展开直接替换为 `batteryLevel=18` 等冷冰冰参数，未能升华为具身体验的拟人叙事。通用角色缺乏具体生活偏好与口头禅（Persona Quirks），容易趋于平庸礼貌。
4. **断层四：真机物理环境的保活与长周期打扰度标定空白**：全工程 597 项测试均为 JVM (Robolectric) 单元测试。国内厂商系统（HyperOS、ColorOS、OriginOS）对无障碍与前台保活有严苛杀后台机制；InterruptibilityEstimator 的打扰代价参数缺乏真机 24 小时真实节律实测标定。

## 四、四大核心子系统深度工程规格设计

### 4.1 子系统一：情境感知沉淀与入梦升华流水线 (Episodic Consolidation Pipeline)
1. **核心职能**：将白天发生的无声陪伴以极低开销聚类为情境切片（Episodic Slice），并在夜间自叙梦中提炼为自叙生活回忆（Track B）。
2. **数据模型 (EpisodicSensingSliceEntity)**：包含 id, timestampMs, dwellDurationMs, appCategory, primaryPackage, summaryScene, hardwareContextJson, isConsolidated。
3. **缓冲管道 (SensingEpisodicBuffer)**：前台交互 >=3 分钟或物理状态跳变时入库；单日上限 50 条切片，FIFO 滚动，全天额外 DB 占用 <15KB。
4. **夜间入梦 (DreamEpisodeConsolidator)**：SubconsciousDreamCoordinator 调用端侧/BYOK LLM 提炼当日陪伴生活大纲，写入 `self_experiences` 表。

### 4.2 子系统二：开环记忆生命周期状态机与关怀调度 (Open Loop Lifecycle & Care Engine)
1. **核心职能**：追踪对话中的未决事项，维持开环张力，到期关怀破冰，事后闭环核销。
2. **数据模型 (OpenLoopEntity)**：包含 id, sourceMemoryId, title, targetTimeMs, triggerWindowStartMs, status (OPEN/TRACKING/TRIGGERED/RESOLVED/EXPIRED), urgencyLevel, followUpPrompt, retryCount, lastPromptedMs。
3. **状态机流转 (OpenLoopLifecycleManager)**：
   - `OPEN -> TRACKING`：进入 triggerWindowStartMs 关怀窗口；
   - `TRACKING -> TRIGGERED`：命中 SCREEN_UNLOCK 天然断点，递出关怀破冰；
   - `TRIGGERED -> RESOLVED`：用户反馈完成，MemoryExtractor 识别打上 RESOLVED；
   - `TRIGGERED -> EXPIRED`：超期 72h 未提及自动降级归档。

### 4.3 子系统三：具身生活叙事引擎与 Presence 在场感演化 (Embodied Narrative & Presence Model)
1. **核心职能**：将硬件数据映射为具身第一人称叙事，建立 4 级在场感模型。
2. **转译器 (EmbodiedNarrativeTranslator)**：耳机听歌 -> 沉浸私密世界；深夜低电量未充 -> 疲乏虚弱；清晨拔线 -> 准备出门；长期待机解锁 -> 久别相聚。
3. **Presence 四级在场状态机**：
   - `ASLEEP`：深夜充电息屏，静默入梦；
   - `LOITERING`：办公专注，悬浮窗收缩至极小微表情；
   - `COMPANIONING`：休闲娱乐，微表情共振，弱注视微气泡浮现 4 秒淡出；
   - `ENGAGED`：主聊天打开，全功能心智激活。

### 4.4 子系统四：Helix-GUI 操控底座升维与 Waterfall 权限门坚守 (Grounding & Safety Guard)
1. **核心职能**：解决无文字纯图标按钮定位困难，守住安全物理层，贯彻 PRD D5 诚实失败原则。
2. **三级混合接地**：L1 无障碍树语义查找 (<20ms) -> L2 端侧 ML Kit 离线 OCR (<180ms) -> L3 图标几何语义启发式锚定。
3. **Waterfall 权限门与零信任护栏**：
   - Tier 0 物理绝缘区：微信代发、银行金融、密码框绝对物理熔断；
   - Tier 1 敏感操作：弹窗确认卡片带 5 分钟 Token；
   - 诚实失败原则：无法执行时 HonestNarrator 人设化坦白，严禁伪造成功。
