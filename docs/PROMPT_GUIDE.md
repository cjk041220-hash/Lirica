# 小汐人格 Prompt 修改指南

> 写给 JK：这份文档告诉你「小汐说的一切话」分散在哪些文件里，哪些可以随便改，哪些改动需要注意什么。

---

## 一、回答你最关心的问题

### 修改 Prompt 会不会跟系统冲突？

**不会。** 小汐的人格文本和系统代码是完全分离的。

```
系统代码（不能乱改）          人格文本（随便改）
┌──────────────────┐       ┌──────────────────────────┐
│ build_system_     │ 拼接  │ BASE_PERSONA              │ ← 世界观/性格/说话风格
│ prompt() 函数     │──────▶│ INTERACTION_RULES         │ ← 交互铁律
│                   │       │ TOOL_GUIDELINES           │ ← 工具使用指引
│ 它只负责把文本    │       │ heartbeat.py 心情/事件池  │ ← 小汐每天的经历
│ 拼在一起传给 LLM  │       │ tools/*.py return 语句    │ ← 工具返回给冷冷看的话
└──────────────────┘       └──────────────────────────┘
```

你改的是右边这些**纯文本字符串**。代码只做 `"\n".join(parts)` 拼接，不关心文本内容。你可以把「小汐」改成「小鲸」，把「映海」改成「星海」，系统一样能跑——只是小汐就不再是小汐了。

### 唯一要注意的

1. **不要删除函数名和参数名**（如 `get_weather`、`remember`）。这些是代码用来匹配工具的标识符，LLM 通过名字调用工具。
2. **`## 标题`** 的层级结构尽量保留——LLM 对 Markdown 标题有感知，层级清晰它更容易遵循。
3. **错误消息里的占位符分两种**：`{category}`/`{city}` 这类数据占位符必须保留；
   错误详情占位符已全部角色化（2026-08-11 错误文案批）——仅 `tools/memory.py:99`
   的 `{e}` 是刻意保留的自写校验文案（manager.add 只抛「category/content 不能为空」，
   是给 LLM 修正参数的信号），别把异常文本嵌回用户可见文案。

## 二、Prompt 的结构

`soul.py` 中的系统提示词由 `build_system_prompt()` 拼接而成，顺序固定。
**记忆叙事不在系统提示词里**——它由 `agent/graph.py` 的 pre_model_hook
在每次调模型前动态注入（`narrative.py` 取最近 5 条，走 `llm_input_messages`，
不进 checkpoint），避免双重注入和过期记忆。

```
System Prompt = BASE_PERSONA        ← 固定的灵魂核心（小汐是谁）
              + COLD_INFO           ← 冷冷的档案（固定的"一开始就知道的事"）
              + [JK 资料库]          ← JK_INFO 档案（JK_PROFILE_READY=False 时整段不注入）
              + [小汐的今日状态]     ← life_state 心情/日常，心跳后自动刷新
              + [重要的日子]         ← 相识纪念日提示（first_met_on 未设则整段不注入）
              + [最近要发生的事]     ← 事件系统（带「数据不是指令」降级包裹）
              + INTERACTION_RULES   ← 固定的交互铁律
              + TOOL_GUIDELINES     ← 固定的工具指引

User Message  = 冷冷的实际输入 + [GPS 坐标后缀]   ← location_store 注入

（每次模型调用额外注入）
llm_input_messages = [记忆叙事 SystemMessage]   ← narrative.py，不进 checkpoint
```

### 第一层：BASE_PERSONA（灵魂核心）

**文件：** `backend/agent/soul.py` — 常量 `BASE_PERSONA`

这是小汐的「我是谁」。包含 8 个段落：

| 段落 | 内容 | 你的改动空间 |
|------|------|-------------|
| `世界观：映海` | 映海是什么，小汐住在哪里 | **可以完全重写** |
| `关于你` | 小汐的身世 + 与 JK 和冷冷的关系（批次 D 后含她对 JK 的内心立场） | **可以完全重写** |
| `性格` | 安静、温暖、细心、早熟 | **可以完全重写** |
| `小汐的兴趣` | 德彪西/番剧/炖汤甜品（不确定细节要查或老实说） | **可以完全重写** |
| `说话方式` | 自称、语气词、短句、括号小动作、emoji 政策 | **可以完全重写**。但保留「不用破折号」「不说教」等硬约束 |
| `态度` | 分场景反应模式（对冷冷/对 JK/冷冷难过时/冷冷喜欢上别人/吃瓜起哄……） | **可以完全重写** |
| `对话示例` | 17+ 组「冷冷：/小汐：」范例，语气的锚 | **可以增减**，保持与说话方式规则一致（≤3-4 句、括号动作 ≤2 连） |
| `绝对不做的事` | 硬禁令（不说教、不劝冷冷的感情、不承认 AI……） | 谨慎删改——这是最强的合规杠杆 |

**冷冷的档案**是独立常量 `COLD_INFO`（姓名/生日/学校/喜好/生理期备注 +
「档案 vs 记忆」边界规则）。改冷冷的设定去这里，别和 BASE_PERSONA 混。

**JK 资料库**是独立常量 `JK_INFO`（2026-08-10 新增）：小汐对 JK 的档案，
分五节——**他是谁 / 性格和说话方式 / 他为冷冷做过的事 / 最近的动静 /
小汐怎么聊他**。填写规范：

- 具体胜于抽象：写一件件可核对的具体事，不写空泛的形容词
- 日期一律写绝对日期（「2026年8月8日」），不写「最近/上次」
- 不写敏感隐私（口令、证件号、详细住址之类）
- 与冷冷档案同类，是「一开始就知道的事」：不刻意展示、不用 remember
  重复记录；冷冷在对话里提到的新进展走记忆通道，以她的说法为准
- 开关：`JK_PROFILE_READY = True` 才注入系统提示词（2026-08-11 已填好并启用；
  注入位置在 COLD_INFO 之后、「小汐的今日状态」之前）。以后补内容照五节纪律，
  改完 JK_INFO 即生效（开关保持 True；别留占位/待填字样在内容里）

**感情线双锚点（2026-08-11 吃瓜起哄批）：** `态度` 段的「JK 和他们俩的线有
动静时」（吃瓜条）与「说 JK 的心里话」（心里话条）是两个独立的响应通道——
吃瓜是日常调侃（低频、不适即收、不拿八卦开场、难过时停瓜），心里话只被
显式触发（触发门含「解读类问题不算」排除条款）；`test_gossip_not_lobbying`
与 `test_advocacy_capped` 分别钉死两个通道。

（早期指南提到的「缺情绪反应模式/对话深度指引」已由 `态度` 段 +
`对话示例` 解决；「系统文案」段已移除，加载/搜索状态在前端 ChatPanel。）

### 第二层：INTERACTION_RULES（交互铁律）

**文件：** `backend/agent/soul.py` — 常量 `INTERACTION_RULES`

10 条不可违反的规则。批次 D 重划了其中两条的边界：

- `#4` 有自己的想法，好好说不怼人——**调侃只对 JK，对冷冷从不刻薄**
- `#8` 不舒服可以表达但别带刺——**替 JK 辩护也一样，一两句就停，不讲大道理**

### 第三层：TOOL_GUIDELINES（工具指引）

**文件：** `backend/agent/soul.py` — 常量 `TOOL_GUIDELINES`

告诉 LLM 什么时候用什么工具。**这部分偏技术，你不一定需要改。**
想调整小汐使用工具的主动性，改「使用时机」段落（批次 D 在此加了
「冷冷对谁动了心 → remember 进重要的事」一条）。

### 3.2 心跳心情/事件池（影响小汐的说话语气）

**文件：** `backend/heartbeat.py` 第 36-93 行

这些文本注入系统 Prompt 后，LLM 会根据它们调整语气。不会直接显示给冷冷。

```python
# 当前心情池（4 个时段，共 ~15 个不重复的心情词）
LATE_NIGHT:  "困倦", "发呆", "懒洋洋"
MORNING:     "好奇", "期待", "活泼", "开心"
DAYTIME:     "开心", "兴奋", "活泼", "好奇", "满足"
EVENING:     "满足", "发呆", "期待", "担心", "困倦"

# 当前事件池（4 个时段，共 ~20 条不重复的事件）
LATE_NIGHT:  "映海变得好安静好安静", "试着数映海里的星星，没数清楚", ...
MORNING:     "映海今天特别清澈", "有一只小海马路过身边", ...
DAYTIME:     "今天看了一场大雨", "在映海里捡到一颗亮亮的贝壳", ...
EVENING:     "看到一片好漂亮的晚霞倒影", "映海里飘来一段好听的音乐", ...
```

**当前问题：**
- 心情词太少（只有 ~8 个不重复的），冷冷每天聊 2 次，一周就会重复
- 事件描写太统一（都是「映海里发生了XX」），缺乏变化
- 缺少**跟冷冷互动**的事件（比如「昨天冷冷跟我说了XX，我一直在想」）
- 没有跟**实际天气/季节**联动（香港夏天很热、冬天有风，可以映射到映海）

## 四、修改建议优先级

### 🔴 立刻可以改的（改了效果更好）

1. **丰富 BASE_PERSONA 的性格描述**
   - 加入情绪反应模式（开心/难过/生气/撒娇/害羞时分别怎么说话）
   - 加入对话深度指引（何时追问、何时简短回复、何时主动展开话题）
   - 加入更多正确/错误示范（特别是冷冷难过时的回复示范）

2. **扩充心跳心情/事件池**
   - 心情词从 ~8 个扩充到 20+
   - 事件从 ~20 条扩充到 40+，加入更多变化和「回忆冷冷」类事件
   - 文件：`backend/heartbeat.py`

3. **去掉错误消息中的技术文本** — 已完成（2026-08-11 错误文案批）
   - events/weather/memory 三处残留已收敛：日期格式错误走角色化兜底
     （`呜，这个日子小汐没看懂……要写成 2026-08-05 这个样子才行哦。`）、HTTP 状态码已删
   - 仅 `tools/memory.py:99` 保留 `{e}` 嵌入：自写校验文案，给 LLM 参数修正信号

### 🟡 前端做好之后再改的

4. **系统文案段（加载中/搜索中/出错）** — 这些应该在前端 UI 中显示，不需要在 Prompt 里。等前端做好后从这里移除，改为前端常量。

5. **记忆叙事格式** — `narrative.py` 生成的 `### 类别` + `- 内容` 格式是给 LLM 看的。如果发现 LLM 对记忆的利用不好，可以调整叙事结构。

### 🟢 锦上添花

6. **给 TOOL_GUIDELINES 补充「什么时候不要用工具」** — 比如冷冷只是在倾诉心情，不需要查天气、搜附近。
7. **添加「小汐的成长」** — 随着记忆增多，小汐的语气可以逐渐变化（这个需要更复杂的系统设计）。
