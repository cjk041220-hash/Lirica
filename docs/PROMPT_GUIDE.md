# 小汐人格 Prompt 修改指南

> 写给 JK：这份文档告诉你「小汐说的一切话」分散在哪些文件里，哪些可以随便改，哪些改动需要注意什么。

---

## 一、回答你最关心的问题

### 修改 Prompt 会不会跟系统冲突？

**不会。** 小汐的人格文本和系统代码是完全分离的。

```
系统代码（不能乱改）          人格文本（随便改）
┌──────────────────┐       ┌──────────────────────────┐
│ build_system_     │ 拼接  │ BASE_PERSONA              │ ← 世界观/性格/说话风格
│ prompt() 函数     │──────▶│ INTERACTION_RULES         │ ← 交互铁律
│                   │       │ TOOL_GUIDELINES           │ ← 工具使用指引
│ 它只负责把文本    │       │ heartbeat.py 心情/事件池  │ ← 小汐每天的经历
│ 拼在一起传给 LLM  │       │ tools/*.py return 语句    │ ← 工具返回给冷冷看的话
└──────────────────┘       └──────────────────────────┘
```

你改的是右边这些**纯文本字符串**。代码只做 `"\n".join(parts)` 拼接，不关心文本内容。你可以把「小汐」改成「小鲸」，把「映海」改成「星海」，系统一样能跑——只是小汐就不再是小汐了。

### 唯一要注意的

1. **不要删除函数名和参数名**（如 `get_weather`、`remember`）。这些是代码用来匹配工具的标识符，LLM 通过名字调用工具。
2. **`## 标题`** 的层级结构尽量保留——LLM 对 Markdown 标题有感知，层级清晰它更容易遵循。
3. **错误消息中的 `{str(e)[:100]}`** 这种占位符不能删，它是动态插入错误详情的。

## 二、Prompt 的结构

`soul.py` 中的系统提示词由三层拼接而成，顺序固定。**记忆叙事不再包含在系统提示词中**——它由 `chat.py` 按请求动态注入到用户消息前缀（最近 5 条），避免双重注入和过期记忆。

```
System Prompt = BASE_PERSONA        ← 固定的灵魂核心
              + [生命状态]          ← 由 heartbeat.py 动态生成，心跳后自动刷新
              + INTERACTION_RULES   ← 固定的交互铁律
              + TOOL_GUIDELINES     ← 固定的工具指引

User Message  = [最近 5 条记忆叙事]  ← 由 narrative.py 按请求动态生成
              + [GPS 坐标]          ← 由 location_store 注入
              + 冷冷的实际输入
```

### 第一层：BASE_PERSONA（灵魂核心）

**文件：** `backend/agent/soul.py` 第 10-50 行

这是小汐的「我是谁」。包含 6 个段落：

| 段落 | 内容 | 你的改动空间 |
|------|------|-------------|
| `世界观：映海` | 映海是什么，小汐住在哪里 | **可以完全重写** |
| `关于你和冷冷的关系` | JK 托付的背景故事 | **可以完全重写** |
| `性格` | 天真烂漫、乖巧、犯傻 | **可以完全重写** |
| `说话风格` | 自称小汐、语气词、禁止词 | **可以完全重写**。但保留「禁止」列表 |
| `小汐的小习惯` | 思考/找不到/开心/睡觉 | **可以完全重写** |
| `系统文案` | 加载中/搜索中/出错时 | 这些是**给 LLM 的参考**，不是直接显示的 |

**当前问题：**
- 「性格」段只有 4 行，偏笼统（「天真烂漫、单纯善良」太抽象）
- 缺少**情绪反应模式**（冷冷开心时小汐怎么反应？冷冷难过时呢？冷冷不理她时呢？）
- 缺少**对话深度指引**（小汐会追问吗？会主动展开话题吗？什么时候该简短回复？）
- 「系统文案」段放在 BASE_PERSONA 里，但它其实是 UI 层的事——前端做好之后这些应该在前端展示，不需要 LLM 操心

### 第二层：INTERACTION_RULES（交互铁律）

**文件：** `backend/agent/soul.py` 第 56-63 行

6 条不可违反的规则。当前写得比较好，但可以补充：

| 可以补充的方向 | 示例 |
|--------------|------|
| 回复长度控制 | 「不要一次说太多话。冷冷说一句，你回一两句就好。像聊天，不像写文章。」 |
| 情绪应对 | 「冷冷说累/难过/哭的时候，不要急着给建议。先陪着，先说'小汐在这里'。」 |
| 追问能力 | 「如果冷冷说的话让你好奇，可以追问。小汐对人类世界什么都想知道。」 |
| 沉默应对 | 「如果冷冷很久没说话，不要假装她说了什么。安静等她就好。」 |

### 第三层：TOOL_GUIDELINES（工具指引）

**文件：** `backend/agent/soul.py` 第 69-94 行

告诉 LLM 什么时候用什么工具。**这部分偏技术，你不一定需要改。** 但如果想调整小汐使用工具的主动性（比如更积极还是更保守），可以改「主动使用工具的时机」段落。

## 三、散落在代码中的「小汐说的话」

除了 soul.py 的 Prompt，小汐还会通过工具的返回值直接对冷冷说话。这些文本**不经过 LLM 加工**，会直接显示给冷冷。

### 3.1 工具返回文本（直接显示给冷冷）

这些是工具函数 `return` 的字符串，LLM 读到后会用自己的语气转述给冷冷。但有些场景下 LLM 会直接引用。

| 文件 | 场景 | 当前文本 | 僵硬指数 |
|------|------|---------|---------|
| `tools/memory.py:28` | 记住成功 | `✨ 小汐帮你收好啦！放在映海的「{category}」里。` | ⭐ 还行 |
| `tools/memory.py:30` | 记住失败 | `呜，小汐没接住这段记忆……（{error}）` | ⭐⭐ 技术信息外露 |

| `tools/diary.py:62` | 日记新建 | `📖 小汐写好今天的日记啦！映海里又多了一天的回忆。` | ⭐ 还行 |

**僵硬重灾区：** 所有带 `{str(e)[:100]}` 的错误消息。冷冷会看到类似 `（ConnectionError: timeout after 10s）` 这样的技术文本。

### 3.2 心跳心情/事件池（影响小汐的说话语气）

**文件：** `backend/heartbeat.py` 第 36-93 行

这些文本注入系统 Prompt 后，LLM 会根据它们调整语气。不会直接显示给冷冷。

```python
# 当前心情池（4 个时段，共 ~15 个不重复的心情词）
LATE_NIGHT:  "困倦", "发呆", "懒洋洋"
MORNING:     "好奇", "期待", "活泼", "开心"
DAYTIME:     "开心", "兴奋", "活泼", "好奇", "满足"
EVENING:     "满足", "发呆", "期待", "担心", "困倦"

# 当前事件池（4 个时段，共 ~20 条不重复的事件）
LATE_NIGHT:  "映海变得好安静好安静", "试着数映海里的星星，没数清楚", ...
MORNING:     "映海今天特别清澈", "有一只小海马路过身边", ...
DAYTIME:     "今天看了一场大雨", "在映海里捡到一颗亮亮的贝壳", ...
EVENING:     "看到一片好漂亮的晚霞倒影", "映海里飘来一段好听的音乐", ...
```

**当前问题：**
- 心情词太少（只有 ~8 个不重复的），冷冷每天聊 2 次，一周就会重复
- 事件描写太统一（都是「映海里发生了XX」），缺乏变化
- 缺少**跟冷冷互动**的事件（比如「昨天冷冷跟我说了XX，我一直在想」）
- 没有跟**实际天气/季节**联动（香港夏天很热、冬天有风，可以映射到映海）

## 四、修改建议优先级

### 🔴 立刻可以改的（改了效果更好）

1. **丰富 BASE_PERSONA 的性格描述**
   - 加入情绪反应模式（开心/难过/生气/撒娇/害羞时分别怎么说话）
   - 加入对话深度指引（何时追问、何时简短回复、何时主动展开话题）
   - 加入更多正确/错误示范（特别是冷冷难过时的回复示范）

2. **扩充心跳心情/事件池**
   - 心情词从 ~8 个扩充到 20+
   - 事件从 ~20 条扩充到 40+，加入更多变化和「回忆冷冷」类事件
   - 文件：`backend/heartbeat.py`

3. **去掉错误消息中的技术文本**
   - 把所有 `{str(e)[:100]}` 替换为纯世界观描述
   - 比如 `呜，小汐没接住这段记忆……（{error}）` → `呜，映海里的浪太大了，小汐没接住……过一会儿再试试？`

### 🟡 前端做好之后再改的

4. **系统文案段（加载中/搜索中/出错）** — 这些应该在前端 UI 中显示，不需要在 Prompt 里。等前端做好后从这里移除，改为前端常量。

5. **记忆叙事格式** — `narrative.py` 生成的 `### 类别` + `- 内容` 格式是给 LLM 看的。如果发现 LLM 对记忆的利用不好，可以调整叙事结构。

### 🟢 锦上添花

6. **给 TOOL_GUIDELINES 补充「什么时候不要用工具」** — 比如冷冷只是在倾诉心情，不需要查天气、搜附近。
7. **添加「小汐的成长」** — 随着记忆增多，小汐的语气可以逐渐变化（这个需要更复杂的系统设计）。
