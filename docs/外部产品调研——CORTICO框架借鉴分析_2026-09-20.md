# 局部调研——Cortico 框架借鉴分析

> **调研日期**：2026-09-20
> **调研对象**：[Pal-AI-Lab/Cortico](https://github.com/Pal-AI-Lab/Cortico)（自称"最好的人格 AI Agent"，实际定位为**事件流驱动的 Agent Harness**）
> **服务对象**：《小汐 2.0 开发计划书》（`docs/主方案——小汐2.0开发计划书_原生自主人格伴生智能体_2026-09-19.md`，下称"计划书"）
> **性质**：只读调研，不涉及本地代码改动

---

## 〇、一句话结论

**Cortico 验证了计划书的大方向（事件驱动、记忆即人格、主动性优先），并且在三个 2.0 尚未给出落地答案的子系统上有可以直接抄的成熟方案：梦系统（自叙轨的落地机制）、记忆分层注入（地图+下钻）、阻断闹钟（自主生活的时间维度）。** 它是 Node 服务端框架，代码不能直接搬进 Kotlin 项目，但架构思想、提示词工程和子系统设计全部可移植，且 MIT 许可无法律障碍。

## 二、架构对比：Cortico 四层 vs 小汐 2.0 五层

| Cortico 四层 | 职责 | 小汐 2.0 对应物 | 对齐评价 |
|---|---|---|---|
| **Core** | 会话、事件流分发、模型调用生命周期、调度、容量控制；**内部零语义** | 前台服务 + 事件总线 + Agent 循环（Kotlin） | 2.0 计划书没有显式的"零语义 Core"概念，感知/心智/执行容易耦合 |
| **Persona** | 上下文构造、认知循环、记忆读写协议——**全部语义的独占者** | Mind Engine（心智中枢） | 对齐良好 |
| **Memory** | 唯一权威持久化载体，**本身被动**，由 Persona 赋予解释 | Room SQLite（用户轨+自叙轨） | 对齐良好，但缺一条架构铁律（见 §3.2） |
| **World** | 与单个外部环境的**唯一边界**：事件投递进、工具声明出；World 之间、World 与 Persona 之间**禁止程序级互调** | 感知中枢 + 执行中枢 | **这是 2.0 最值得抄的一条纪律**（见 §3.1） |
| **Bot** | 装配：选一个 Persona + 一组 World | App 装配层 | 单用户单设备，2.0 可大幅简化 |

关键洞察：**小汐 2.0 的"感知中枢 + 执行中枢"合起来恰好就是 Cortico 的一个 World**——手机本身就是那个外部环境。感知中枢负责把环境变化描述为事件（通知到达、前台 App 切换、屏幕状态），执行中枢负责声明和执行工具（打开 App、输入文本、查询）。Cortico 用这个契约隔离了几十个异构环境（QQ/B 站/Minecraft），2.0 用它隔离"手机"这一个环境，纪律完全通用。

## 三、值得借鉴的十个点（按优先级排序）

### 3.1 ★★★★★ World 边界契约：层间只走"事件 + 工具"，禁止直调

Cortico 规定（PHILOSOPHY.md）：World 与 Persona 不直接依赖，不能调用彼此的程序接口，**只能通过事件投递和工具声明这种语义化形式沟通**。World 提供环境描述（系统提示词段）、事件契约、工具契约；Persona 在语义层理解它们。

**映射到 2.0**：计划书第四节的五层拓扑目前只画了"有什么"，没约束"层间怎么通信"。建议在架构纪律里明确：

- 感知中枢 → 心智中枢：只投递**结构化事件**（类型 + 载荷 + 可验证事实），不传"该怎么反应"的指令；
- 心智中枢 → 执行中枢：只调用**声明过的工具**，执行中枢对"为什么做"无感知；
- 任何一层都不得绕过事件/工具契约直接摸另一层的内部状态。

这条纪律的直接收益：以后做角色卡多实例、或把某个 World 换成别的环境（如桌面端），心智中枢一行不改。

### 3.2 ★★★★★ "Memory 即人格"写成架构铁律

Cortico 原文（PHILOSOPHY.md 人格审美第 1 条）：独立存在的人格 Bot 的主体性和连续性**由它的 Memory 数据完全定义、决定和保证**。模型替换、上下文交接、进程重启都不改变 bot 的人格个体身份。

**映射到 2.0**：计划书 5.1.3 的双轨记忆目前是一个"功能模块"，建议升格为架构第一性原则：

- 换模型供应商（BYOK 场景下用户随时换 key/换模型）→ 人格不变，因为人格在 Room 里；
- 清空会话/重装 App → 只要记忆数据库的加密备份在，人格就在；
- 这直接决定备份/迁移设计：**记忆数据库的导出导入必须是一等公民功能**，而不是附属功能。用户轨 + 自叙轨 + 情绪状态 + 关系图谱全部属于"人格档案"。

### 3.3 ★★★★★ 梦系统（subconscious）：自叙轨与念头池的现成落地机制

计划书 5.1.3 的"自叙轨"和"未完成念头池"目前只有概念定义，没有运行机制。Cortico 的 `corti-soulmate/persona/subconscious/` 给了完整答案：

**触发时机**：主上下文发生交接（context handoff）后，从交接前快照 fork 出一个"睡眠线程"（dream fork），异步整理记忆。**手机端映射：充电 + WiFi + 空闲时段触发，天然省电省 token，和 WorkManager 约束作业完美对齐。**

**梦的职责清单**（prompts.ts 原文要点，已提炼）：
1. 合并 note/ 里的重复条目，相对日期改写为绝对日期；
2. 处理矛盾与无出处声明——保留双方 / 标记存疑 / 降级，自行判断；
3. 跨条目反复出现的模式提炼为摘要；涉及具体人的写进这个人的档案；
4. 关闭已完结的 memo，把失约的后果写回当事人档案；
5. 宪法审查：对照行为准则检查近期行为，偏差记为案例；
6. **WORLDVIEW.md 只做高层综合：一个模式只有在不同日期或真正独立的事件中反复出现才允许晋升进来**；单次事件永远留在日期/人物/笔记层级。

**两条认知纪律（精华中的精华）**：
- **"消化、总结、归纳的内容应该多于追加的内容"**——反囤积，记忆系统不做垃圾场；
- **"区分发生了什么、别人声称了什么、我推断了什么、我现在相信什么"**——记忆条目带认识论标签，这和计划书"诚实的感知"原则完全一致。

**梦醒机制**：梦结束时调用 `surface(text)` 留一段第一人称"睡眠总结"，投递给清醒线程。**这就是"未完成念头池"的天然生产者**——梦里整理记忆时冒出的"想说但现在不适合说"的碎片，沉淀下来就是下一次交互的破冰谈资。

### 3.4 ★★★★☆ 记忆的"地图式"注入：常驻上下文只放索引，细节靠下钻

Cortico 的记忆注入模板（corti-soulmate/persona/MEMORY.md）分五层，值得整段研读：

| 层 | 内容 | 注入方式 |
|---|---|---|
| MEMORY 0·地图 | 记忆目录树 + 手册名列表 | 只给**索引**，原文明确说"地图不是答案，想往里翻自己用工具下钻" |
| MEMORY 1·认知 | WORLDVIEW 综合认知 + 认识的人花名册（roster） | 全文常驻 |
| MEMORY 2·备忘 | memo 时间性工作记忆 | **三分层**：resident 全文常驻 / active 只列名 / archived 只给计数 |
| MEMORY 3·反射 | 最近几场梦的浮现（emergences） | 常驻 |
| MEMORY 4·当下 | 当前时间、时区 | 常驻 |

**对比小汐现状**：`backend/agent/graph.py:104-107` 的 narrative_builder 是 top-5 召回拼接，记忆规模一大就会挤爆预算且召回不稳。地图式注入的记忆规模可以无限大——常驻 token 恒定，细节按需 `read_file`。

**memo 三分层直接可抄到 2.0 的日程/任务记忆**：正在进行的事全文注入，活跃的事只列标题，归档的事只报数量。

**roster（认识的人）概念同样可抄**：2.0 泛化到任意角色卡后，角色卡世界观里的 NPC、用户提到的人际关系，都值得一张独立花名册，而不是混在用户画像里。

### 3.5 ★★★★☆ 上下文交接（onHandoff）：裁剪之前先生成"交接快照"

Cortico 把上下文容量调度做成 Persona 显式策略：容量不足时先产出 handoff snapshot（含 tail 与 trim 策略），新上下文从快照冷启动；corti-soulmate 更进一步——**交接动作本身就是触发梦的时机**。

**对比小汐现状**：`backend/agent/graph.py:68-83` 的裁剪逻辑是"找 HumanMessage 边界、宁多留勿切链"，纯机械，被裁掉的内容语义上就丢了。借鉴方向：

- 裁剪前先让模型（或廉价小模型）为即将出局的消息段生成一份**交接摘要**（聊到哪了、悬而未决的事、情绪状态），随记忆叙事一起注入；
- 端侧场景可以在裁剪发生时顺手入梦（触发 3.3 的整理流程），一次裁剪 = 一次记忆巩固。

### 3.6 ★★★★☆ 主动性哲学的折中落地："机械漏斗过滤 + 模型终审"

Cortico 哲学（人格审美第 2 条）：最大限度保证主动性，**以不行为为默认行为**，允许 bot 自行判断是否行动；需要约束时用上下文语义约束代替机械阻拦（硬安全、权限、不可逆副作用除外）。

**映射到 2.0 的现实**：计划书 5.5 的主动性裁决器是纯机械的"特征提取 → 认知负荷打分 → 沉默/发声决策"。纯语义裁决在服务端可行（Cortico 每个事件都唤醒模型），在手机端会被 token 成本和电量打死。**建议折中架构**：

1. 端侧低能耗感知漏斗（计划书 5.2）保留——它负责**过滤掉 95% 不值得唤醒模型的情境**；
2. 漏斗终点不再机械决定"说不说"，而是把情境打包成事件投递给模型，**由模型在语义层自己决定是否行动、说什么**——这是 Cortico "以不行为为默认行为"的端侧化版本；
3. 机械层只保留三类硬规则：隐私熔断（计划书已有）、成本/频率上限、夜间硬勿扰——且按 Cortico "最小先验干预"原则，**每条硬规则必须在系统提示词里向模型显式声明**（"你现在处于勿扰时段"），而不是静默拦截让 bot 莫名其妙。

### 3.7 ★★★☆☆ schedule_wake 阻断闹钟：自主生活循环的时间维度

`corti-soulmate/persona/rhythm.ts` 实现了 bot **给自己定闹钟**的完整语义：

- `schedule_wake(at 或 after_minutes, note, block?)`：到期时注入 `[system/wake] My note: "..."`，bot 用自己的话记着"我为什么定了这个闹钟"；
- **block 模式（阻断投递闸门）**：闹钟响起前，外部事件全部排队不投递；唤醒关键词命中或积压超过 overflow_limit 才放行——相当于 bot 说"我到点了才处理外界的事"；
- 簿记完整：note、setAt、id 全部回执给模型，符合"诚实的认知论"。

**映射到 2.0**：这就是"自主生活循环"的调度原语。角色卡说"我晚上十一点要写日记"、"两小时后提醒她喝水"，落到 Kotlin 就是持久化的 WorkManager 作业 + 事件投递闸门。**关键设计点是闹钟语义对模型可见**（note 回执），而不是一堆后台 cron——bot 知道自己定了什么约定，才算"自己的"生活。

### 3.8 ★★★☆☆ 起草-确认门：主动发声与代操作的安全阀

corti-soulmate 在 QQ World 上有"起草-确认门"：bot 生成消息草稿，经确认后才真正发出。**映射到 2.0 的"发送微信草稿"场景**（计划书 1.2）：任何涉及外部副作用的动作（发消息、打卡、删除）都应先落草稿、给用户过目——与计划书 5.4 的"敏感操作守门员（Human-in-the-loop）"完全同向，可以直接采用它的交互模式：草稿 = 一张可编辑的确认卡，而不是一句口头询问。

### 3.9 ★★★☆☆ 会话开场与会话族谱（sessionHead / declareSessions）

Cortico 的 Persona 可以声明多个 session（恰好一个持久接收事件的 session），每次请求现取 `sessionHead()`（置于 system 之后、历史之前的轻量开场，**不落盘**）。这解决了"开场状态每轮重复注入"和"开场内容污染历史"的矛盾。

**映射到 2.0**：小汐 1.0 的 `soul.py` 是一整块静态巨型提示词。2.0 的上下文构造建议拆成 Cortico 式的有序段：PREFIX（宪法）→ 记忆地图 → 环境段（感知摘要）→ 历史 → PHI 重锚。每段独立演化、独立测试，角色卡引擎的模板变量（`{{current_app}}` 等）只污染环境段。

### 3.10 ★★☆☆☆ AI 协作开发纪律：AGENTS.md 词表与假数据核验面

Cortico 全程 AI 协作开发，沉淀了三条可复用的工程纪律：

1. **AGENTS.md 词表定死**：同一概念全仓库只允许一个词（config 一律叫"配置"，"参数"只留给工具入参）——AI 改代码时歧义显著减少；
2. **dev-console 假数据核验面**：前端改动先用假数据跑一遍完整页面流，不依赖真部署；
3. **贡献者必须能解释所有代码**：AI 生成、人签名，责任在人。

2.0 由 Claude Code 主力落地，这三条直接写进 2.0 的 `AGENTS.md`/`CLAUDE.md` 即可。

## 四、不适合照搬的部分（避坑清单）

| # | 不照搬的理由 |
|---|---|
| 1 | **代码本身不可移植**：Node/TypeScript 服务端框架 vs Kotlin 原生 App，只有思想可搬 |
| 2 | **多部署/多 session/多 World 的复杂度**：Cortico 支持一个进程跑多台 bot、挂多个环境；2.0 是单用户单设备单 bot，Core 层应该比它简单一个数量级，别把"多部署管理器"也抄进来 |
| 3 | **无移动端痛点方案**：保活、电量分级、隐私熔断、无障碍树提取——Cortico 一概没有，这些仍是 2.0 要自己解决的问题（计划书 5.2/5.3 的设计不被本次调研推翻） |
| 4 | **SillyTavern 角色卡泛化**：Cortico 的 Persona 是写死的类，没有角色卡动态加载需求；2.0 的角色卡引擎（PNG 解码/宏/世界书）是差异化能力，不要为了向它靠拢而放弃 |
| 5 | **"事件必唤醒模型"的纯语义主动性**：服务端电费无所谓，手机端必须有低能耗漏斗（见 §3.6 的折中） |
| 6 | **pre-release 状态**：09-13 才开源，API 未冻结，不要基于它的代码结构做长期依赖规划，只做思想引用 |

## 五、对计划书的具体修订建议（五处）

| # | 计划书位置 | 建议修订 |
|---|---|---|
| 1 | §四 五层拓扑 | 增加层间通信纪律：感知→心智只投递结构化事件，心智→执行只调用声明工具，禁止跨层直调（§3.1） |
| 2 | §5.1.3 双轨记忆 | 补"Memory 即人格"铁律 + 记忆档案导出导入为一等公民功能（§3.2）；自叙轨落地机制指向梦系统设计（§3.3） |
| 3 | §5.1 心智中枢 | 上下文构造从"单块提示词"改为分段组装：宪法前缀 / 记忆地图 / 环境段 / 历史 / PHI；记忆注入采用地图+下钻模式，memo 用三分层（§3.4、§3.9） |
| 4 | §5.5 主动性裁决器 | 从"打分决策"改为"机械漏斗过滤 + 模型终审"，硬规则向模型显式声明（§3.6）；自主生活循环引入"bot 自定闹钟 + 投递闸门"原语（§3.7） |
| 5 | §六 Phase 路线图 | Phase 0 的技术验证清单可加一项：梦系统最小原型（空闲时段触发的记忆整理作业 + surface 浮现），验证 WorkManager + Room + 提示词链路 |
