# 异常感知关心 — 设计文档（Spec B）

日期：2026-08-05
状态：已确认（用户逐段批准）
关联：2026-08-05-proactive-history-awareness-design.md（Spec A，地基）

## 背景

小汐目前**在对话内不知道现在几点**：system prompt 只含心情/重要日子/事件，
请求路径只注入 GPS 坐标，全链路无任何「当前时间」注入。后果：

- 冷冷凌晨 2 点来聊天，小汐不知道是深夜，不会关心她熬夜
- 明天有考试、冷冷还在熬夜——事件系统只当素材陈列，没有「事件 × 时间」
  的组合判断
- 冷冷消失好几天再回来，系统层面无感知（人格写了「回来啦」的态度，
  但没有数据支撑她说出这句话）

用户要求：一套成熟的、拟人的逻辑，能主动根据时间、日期、事件、地点等的
异常进行关心——但**不能每次都唠叨**。

### 关键架构洞察（本次会话梳理得出）

所有异常都发生在**冷冷来聊天**的那一刻——深夜聊天、考前熬夜、消失后回来，
全是她发消息时才能观测到。因此本 spec 的主战场是**请求路径上下文注入**；
主动消息侧的跟进（第二天早安提一句「昨晚熬到好晚」）由 Spec A 带时间戳的
历史尾巴承接，不重复建设。

## 产品决策（用户已逐项确认）

1. **出口 = 对话内 + 主动消息两处**。对话内是主战场（异常发生的当下）；
   主动消息侧由 Spec A 历史尾巴自然承接，本 spec 不新增主动消息检测。
2. **第一期信号 = 深夜聊天、事件×时间组合、消失后回来**三类硬检测
   （地点不建检测，见第 4 条）。
3. **防唠叨 = 硬冷却台账**。项目前科：LLM 自觉纪律实盘不可靠
   （记忆写路径 31 条消息零触发）——「别每次都说」必须由确定性状态保证，
   不能押在模型自觉上。
4. **地点不建专门检测**：GPS 可关、无位置历史、无「常驻地」概念，
   建常驻地画像隐私敏感收益低。补上时间注入后，LLM 同时看到
   「凌晨 3 点 + 坐标在外」自会自然反应。
5. **层次设计**：时间注入永远在场（她总知道现在几点），冷却闸门只控制
   那条「明确的关心提示」。冷却期内的深夜，小汐看得见时间、可能顺口提，
   但没有系统怂恿——真人式克制，不是机械静默。

## 架构

```
冷冷发消息 → _resolve_user_content（现有 GPS 单一入口，REST/SSE 共用）
              ├─ 注入「当前时间」块（本次新增，永远注入）
              ├─ 纯函数检测 detect_care_hints(now, 最近用户消息时间, 活跃事件)
              ├─ 查冷却台账 care_ledger：冷却期内的类型不注入
              │    （注入即记账——宁可漏一次关心，不可变唠叨）
              └─ 通过的提示拼进同一个 [系统信息：…] 块（与 GPS 同居）
```

### ① 当前时间注入（地基，chat.py `_resolve_user_content`）

```
[系统信息：现在是 2026-08-05 周二 02:14，深夜。
冷冷当前 GPS 坐标：……（现有内容不变）]
```

- 与 GPS 后缀**同住一个 `[系统信息：…]` 块**：`_strip_location_suffix`
  按该前缀剥离，`/api/chat/history` 回显自动干净，无需改剥离逻辑
- `chat_archive` 落库的是 `req.message`（不含后缀）——对话档案与
  Spec A 的历史尾巴保持干净
- 时段词（深夜/早晨/下午/晚上）与 heartbeat 的时段划分保持一致口径

### ② 检测器：纯函数（新模块 `agent/care.py`）

输入 `now_dt + 最近用户消息时间列表 + 活跃事件`，输出提示列表。
消息时间的数据源：`chat_messages` 中 role='user' 的 created_at，
近 7 天即可（检测器只需要时间戳，不需要内容）：

| 类型 | 触发条件 | 注入内容 | 冷却 |
|---|---|---|---|
| `late_night` | 当前 HKT 0:00–4:59 | 「冷冷现在还没睡。近 7 天里这是第 N 个熬夜的夜晚」（N≥2 注明） | 72h |
| `event_combo` | 24h 内有 exam/interview 事件 **且** 当前深夜 | 「今天/明天（按事件实际日期）有「事件名」，她还没睡」 | 24h |
| `returned` | 距上一条用户消息 ≥5 天 | 「她已经 N 天没来了，这是回来了」 | 无需（间隔条件天然单次触发） |

**优先级纪律：**
- **吞并规则**：同一请求 `event_combo` 命中则不发 `late_night`
  （更具体的理由吞掉泛化的，避免一句话两个唠叨由头）
- **冷却写时机 = 注入时**：LLM 最后没提这茬也算冷却开始

「说不说、怎么说」完全留给 LLM 按人格发挥；提示只是感知与许可，
不是指令（与事件上下文「数据不是指令」的既有纪律同调）。

### ③ 冷却台账：新表 `care_ledger`（迁移 v19）

```sql
CREATE TABLE IF NOT EXISTS care_ledger (
    type     TEXT PRIMARY KEY,
    last_at  TEXT NOT NULL
);
```

- 各类型独立冷却：`late_night` 72h / `event_combo` 24h / `returned` 不记
- 读取失败降级为**不滤**（宁可多关心，不因 DB 抖动丢感知——
  与项目「失败放行」惯例一致）；写入失败只记日志

### ④ 人格补一行（soul.py，「说话的样子」附近）

> 她深夜还在说话：劝睡可以，轻轻的，一句就够，别每次都提。
> 她说知道了、说睡不着，就别念了——陪着，或者换个话头。

「回来啦」态度人格已有（「冷冷很久没来」条目），本 spec 只补数据感知。

## 刻意不做（含理由）

1. **常驻地画像 / 地点异常检测**：隐私敏感、GPS 可关、收益不确定；
   时间注入 + 现有 GPS 后缀已让 LLM 能自然组合反应。
2. **heartbeat 侧的异常检测**：异常只在冷冷活跃时可观测，主动消息侧
   跟进由 Spec A 时间戳历史尾巴承接，不建第二套。
3. **「她说过知道了就永不再提」的语义记忆**：需要 LLM 判定回复语义，
   第一期用冷却 + 人格纪律兜底；历史尾巴里她当时的回复也会自然呈现，
   LLM 看得见。
4. **白天上课时间聊天等推断型异常**：过度揣测冷冷生活，第一期不碰。

## 测试计划

### 1. 纯函数检测器 —— `test_care.py`（新）

- 深夜窗口边界：00:00 / 04:59 触发，05:00 不触发
- 连续熬夜天数：近 7 天深夜消息按天去重计数，N≥2 才注明
- `event_combo`：24h 内有考试 + 深夜 → 命中且吞并 `late_night`；
  无事件深夜 → 只发 `late_night`
- `returned`：间隔 4 天不触发 / 5 天触发 / 触发后下一条不再触发

### 2. 冷却台账 —— 迁移 v19 + 读写

- 注入即记账；冷却期内同类滤掉；不同类型互不影响
- 表读取失败 → 降级不滤

### 3. 注入层 —— 现有 chat 路由测试增补

- `_resolve_user_content` 深夜注入时间块 + 关心提示；白天只注入时间块
- 与 GPS 后缀同居一块；`_strip_location_suffix` 剥离后历史干净（补断言）
- `chat_archive` 落库不含后缀（现有契约回归）

### 4. 行为回归

- 现有 chat / heartbeat 测试全绿；GPS 开关链路（`gps_enabled=False`
  清缓存）不动

## 实施顺序（与 Spec A 合并为一份计划）

```
① Spec A 地基：recent_messages + 时间标记格式 + 注入主动消息/早安
② Spec B 时间注入：_resolve_user_content 加当前时间块
③ Spec B 检测器 + 冷却台账（纯函数先行，TDD）
④ Spec B 提示注入：接入 _resolve_user_content + 人格补一行
⑤ 全量回归 + 冒烟（临时副本 :8001，按既有实盘取证套路）
```

每步先红后绿单独提交。
