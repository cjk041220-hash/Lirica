# 主动消息对话历史感知 — 设计文档

日期：2026-08-05
状态：已确认（用户逐段批准）

## 背景

小汐的主动消息链路（heartbeat 随机搭话 + 每日早安）目前**对对话历史零感知**：
`_generate_proactive_message()` 的 prompt 只注入心情、日常事件、周末标签、活跃事件、
24h 已发防复读——没有一行来自 `chat_messages`。

后果与人格设定直接冲突：`soul.py` 已有完整的「生气的时候」机制（挑明 / 结束话题不理人 /
冷冷软下来顺台阶下 / 偶尔自己别扭地先递台阶 / 逃生阀说开翻篇），但它只在**实时对话**中
生效。一旦对话在僵局中结束，下一次主动消息仍是欢快随机的「想你~」——昨晚刚吵完，
今早就当什么都没发生，「独立真人」人设在主动消息这条链路上断裂。

同样的失忆也覆盖温和场景：上次聊到一半的事（考试、要去做的事）没有自然跟进，
答应过的事不会自己想起来提。

### 现状链路（实读代码确认）

- `heartbeat.check_and_proactive_message` → `_try_proactive_message` → 闸门
  `_should_send_proactive`（≥7 点 + 距上次 ≥4h + 50% 概率）→
  `_generate_proactive_message(mood, daily_event, hour)` →
  `_store_and_push_proactive`（存 pending → 推送 → 失败降级 stored）
- 对话档案：`chat_messages`（迁移 v8），`memory/chat_archive.py` 提供
  `record_user_message / record_assistant_message / get_messages(session_id)`，
  **没有跨会话取最近 N 条的读函数**
- 早安：`daily_morning_greeting()`（8:00 HKT cron），prompt 含天气 / 日程 / 美食 / 今日一歌，
  同样无对话历史

## 产品决策（用户已逐项确认）

1. **情景范围 = 通用自然发挥 + 跟进聊到一半的事**。不枚举情景（吵架/难过/约定……），
   把最近对话原文喂给生成时的 LLM，由她结合人格自己判断怎么接——最像真人，
   覆盖面最广。「闹不愉快 → 求和/傲娇」是其中最重要的一个特例。
2. **机制 = 直接喂原文尾巴**。否掉的两个方案：
   - 两段式摘要缓存（先 LLM 摘要「上次聊到哪」，缓存至下次对话）——多一次 LLM 调用
     加一套状态维护，YAGNI；
   - 走记忆系统 recall——记忆提取不保证覆盖情绪/约定类信息，可控性弱。
3. **覆盖范围 = 主动消息 + 早安**。早安是每天第一次开口，吵架后的第二天早上最关键。
   前夜提醒（只念日程）与自动日记（已读今日记忆）不动。

## 架构

### 新增纯读函数：`memory/chat_archive.py`

```python
async def recent_messages(limit: int = 20, max_chars: int = 1500) -> list[dict]
```

- 跨会话按 `id DESC` 取最近 N 条 `chat_messages`，反转为时间正序返回
  `[{role, content, created_at}]`
- **不带时间窗口**——闹翻后冷冷三天不来，尾巴仍是那次争吵，正好该求和；
  一个月不来，尾巴恰好支撑「回来啦」。时间窗口反而漏掉这些情况
- 截断保护：单条 content 截 100 字，拼接总量封顶 ~1500 字（约几百 token）
- 提供配套格式化函数，输出 `冷冷：……` / `小汐：……` 交替行文本块，最新在最下
- 空表返回空列表；读取异常由调用方降级处理

### 注入点：`heartbeat.py` 两处

1. `_generate_proactive_message()` —— 随机搭话
2. `daily_morning_greeting()` —— 早安

两处均：调用 `recent_messages()` → 格式化 → 非空则追加历史块 + 引导语到 user prompt。
import 方式遵循现有测试的 patch 习惯（函数内延迟 import），不破坏既有 patch 契约。

### 降级纪律（沿用项目风格）

- 历史读取失败：记日志、省略历史块，**不阻断**消息生成与推送
- 空历史（新库 / 从未对话）：不注入历史块，prompt 回到现状
- 截断兜底、长度过滤、默认文案回退等既有防线全部保留

## Prompt 设计

### 主动消息（历史块追加在现有素材之后）

```
你最近和冷冷说过这些话（最新在最后）：
冷冷：……
小汐：……

接着这个语气和情境自然地搭话。聊到一半没说完的事，可以自己跟进；
如果上次闹了别扭或气氛僵着，按你生气时的性子来——可以别扭地先递
个台阶，可以傲娇一点，但别装没发生过，也别翻旧账。
```

### 早安（历史块追加在天气/日程素材之后）

```
昨晚你们聊到这里（最新在最后）：
……

如果昨晚收尾僵着，早上是你先开口——挑个自然的方式破冰，
别扭一点也没关系。天气、美食、今日一歌照旧。
```

「怎么求和」的行为细节不重复发明——BASE_PERSONA 里「生气的时候」一节已定义
（递台阶 / 说开翻篇 / 不翻旧账），引导语只负责把历史情境与人格条款接上。

## 刻意不做（含理由）

1. **不做冲突检测状态机**：「有没有闹翻」由生成时 LLM 从原文判断。人格本就规定
   不记仇、不翻旧账、说开就翻篇，无需持久化「未和解」状态。
2. **不动触发闸门**：4h 间隔 + 50% 概率保持原样。求和在正常节奏内自然发生
   （最迟几小时内）。「检测到冲突就加速发」需要额外判断逻辑，YAGNI。
3. **防复读机制原样保留**：现有 24h 已发主动消息注入与新历史块并列，互不替代。
4. **前夜提醒、自动日记不动**：前者只念日程，后者已读当日记忆，场景收益小。
