## 一、设计定位：从「工具界面」到「她在场」

Lirica 不是角色市场（星野模式），不是心理治疗面板（Replika 模式），是**单用户、常驻、具身行动的「她」**。UI 的唯一使命：让「她在你手机里活着」可被感知。三条设计原则，全部从产品事实推导：

| 原则 | 推导来源 | UI 含义 |
|---|---|---|
| **1. 在场感优先** | 悬浮窗常驻 + 主动关怀 L1-L3 + 感知管线——她是常驻的，不是点开才存在的 | 深色基调（夜间/常驻场景占比高）；悬浮气泡有「呼吸」微动效；界面节奏安静，避免客服式的高饱和度 |
| **2. 具身即差异化** | M5 行动引擎的 ActionVisualFeedback（触控尾迹/微表情/步骤胶囊）是星野、Replika 都没有的形态 | 视觉语言必须为「她的手」「她的状态」设计组件，而不是只给文本气泡设计 |
| **3. 消除 AI 感** | prompt/人格层一直在做活人感，UI 层不能拖后腿 | 拒绝对话机器人三件套：左右顶格气泡+灰色头像+系统蓝按钮；用非对称、留白、情绪化的小元素替代 |

**明确不做**（对标后主动舍弃）：卡片流角色市场、抽卡/星念式游戏化、3D 化身分屏（无形象资产且与气泡形态冲突）、明亮多彩的娱乐化视觉（C.AI 路线与「安静陪伴」冲突）。

## 三、视觉语言（设计 token 建议）

### 3.1 色彩：深色基底 + 暖点缀

深色优先理由：她是常驻的（夜间通知/息屏送达场景多），深色降低打扰感；Replika 验证了深色+私密感路线在陪伴品类的有效性。**强调色给两个方向待选**（这是人格决策，俊凯拍板）：

| Token | 方向 A「暮色」 | 方向 B「炉火」 | 用途 |
|---|---|---|---|
| `background` | #121417（近黑蓝灰） | #141210（近黑暖灰） | 页面底 |
| `surface` | #1C1F24 | #1E1B18 | 卡片/气泡底 |
| `primary`（她的颜色） | 暮紫 #8B7EC8 | 炉橙 #D98E63 | 气泡、强调、她说话的痕迹 |
| `onPrimary` | #FFFFFF | #1A1410 | primary 之上的文字 |
| `accent`（情绪/记忆） | 雾青 #6FA8A0 | 蜜金 #C9A227 | 记忆徽章、情绪指示 |
| `textPrimary` | #E8E6E3 | #EDE8E2 | 正文 |
| `textSecondary` | #9A9AA0 | #A39C93 | 次要信息 |
| `danger` | 柔红 #C75450（金融拦截/破坏性操作，唯一高饱和） | 同左 | 闸门拦截/确认弹窗 |

铁律：**除 danger 外全部低饱和**；58 处硬编码颜色迁移时逐个归入 token，不在 token 外新增颜色（验收 grep=0）。

### 3.2 字体与字号

- 系统默认中文字族（不引入字体文件，控包体）；重点做**层级与行高**：聊天正文 16sp/行高 1.6（陪伴对话的可读性基准）、次要 13sp、标题 18sp Medium。
- 「她的话」与「你的话」在字号上一致、在容器上区分（见 3.3），字号差异会制造地位感，不要。

### 3.3 形状与容器

- 圆角体系：气泡 20dp（大圆角=柔和）、卡片 16dp、按钮 12dp、悬浮气泡为**动态圆形**（呼吸缩放 2%：IDLE→OBSERVING 状态差可直接读出）。
- 消息容器：她的消息**不画气泡框**，用 primary 色的左侧 3dp 竖线 + 留白分组（消除"客服对话"感）；你的消息保留轻气泡（surface 色）。
- 非对称布局：她的内容靠左出、你的靠右收，但留白不对称（左侧 16dp / 右侧 48dp），打破镜像机器感。

### 3.4 动效（具身层）

| 动效 | 场景 | 规格 |
|---|---|---|
| 呼吸 | 悬浮气泡 idle | 2% 缩放，周期 3.5s，ease-in-out |
| 落笔 | M5 TouchTrace | 贝塞尔尾迹 200ms 淡出，primary 色 30% 透明 |
| 思考 | 流式响应等待 | 三点+光斑缓慢脉动，禁止"转圈"（loading spinner=机器感） |
| 打断 | USER_INTERRUPTED | 气泡收缩+变暗，配文案「你先用，我等着」（文案已有） |

动效铁律：所有动画时长 ≤350ms、可关（设置项「减弱动效」，无障碍要求）。

## 五、约束与红线

1. **状态层零改动**：ChatViewModel(542行)/OverlayExpandViewModel(389行) 只读不碰；本规划纯视觉层与组件层。
2. **悬浮窗性能约束**：常驻服务，动效必须走 `withFrameNanos` 单动画协程，禁多独立动画源；气泡内存目标 <15MB。
3. **颜色迁移策略**：建 token → 每文件替换 → `grep -rn "Color(0x" app/src/main --include="*.kt"` 归零验收 → 跑 882 单测确认无回归。
4. **测试同步**：现有 UI 契约测试（ChatUiPerformanceTest 等 882 项中的 UI 部分）随改动同步更新，不得删除断言。
5. 每轮交付物落 docs/，红线 grep 校验照旧。

## 六、待俊凯拍板的 3 个决策点

1. **强调色方向**：A「暮紫」（冷静疏离的陪伴感）还是 B「炉橙」（温暖在场感）？——这是她的性格色，影响全部组件。
2. **她的消息容器**：竖线留白方案（§3.3，激进、去客服感最彻底）还是保留传统圆角气泡（稳妥）？建议先做竖线方案，真机看不适应再退。
3. **MoodDebugPanel 去留**：升级为正式「心境面板」暴露给日常 UI，还是保持调试隐藏入口？涉及"她的内心被看见多少"的人格边界，建议由你定。
