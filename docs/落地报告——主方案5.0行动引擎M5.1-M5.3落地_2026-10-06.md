## 二、关键设计裁决（写下来防止被后人"优化"掉）

1. **安全裁决服务不是 Layer 2 的一部分**（复审 R7）。它被 Layer 1 通道入口与 Layer 2 编排共同调用，因此放在独立包 `automation/policy`，而不是收进 orchestration。
2. **自触发抑制是抢占熔断能成立的前提**。`dispatchGesture` 注入的手势同样产生 `TYPE_TOUCH_INTERACTION_START`，不做抑制窗口，任务会在第 1 步自我中断。
3. **"用户停手 ≠ 用户同意继续"**（R4）。默认不自动恢复，只有显式"继续"才解除；5 秒静默恢复保留为可配置项且默认关闭。
4. **"没看清" ≠ "没生效"**。页面持续震荡时返回 `Unstable`，不消耗自愈额度——否则加载慢的页面会烧光 3 次自愈与 120 秒预算。
5. **模型不能自造坐标**。决策层只能用 refId 指代目标，文本/资源 ID 由本层从观测快照回填，接地层与安全闸门才有审查对象（`LlmDynamicStepPlanner.refQuery`）。
6. **锚点接地的优先级低于语义接地**。语义能扛布局改版，锚点不能；锚点只在语义歧义消解与语义完全失配时兜底，且用独立 `GroundingSource.NORMALIZED_ANCHOR` 标记，便于从指标里看出"接地质量是否在退化"。
7. **宏录制只在显式声明意图签名时发生**。否则一次性的点击序列会把宏库塞满噪音，回放收益被误命中抵消。
8. **取消任务即撤销全部待确认凭证**（`revokeAll`），杜绝"确认了但没派发"的悬挂授权。
9. **装配期缺陷必须显式失败**：`AtomicActionExecutorBridge` 未绑定时返回明确失败，而不是静默 no-op——静默 no-op 会把"没接线"伪装成"操作成功但屏幕没反应"。

## 五、M5.0 真机冒烟清单（前置硬门禁 · 待用户执行）

> 方案 §10.1 把 M5.0 定为 M5.1 的前置硬门禁。本次实施完成了全部代码级交付与单测，
> **但真机链路未验证**——这一项必须由持有设备的人完成，不能由单测代替。

1. **基础链路**：安装 `app-debug.apk` → 开启无障碍 → 从系统设置授权（含新增的日历、修改系统设置两项）
   → 原生 API 闹钟直达 → A11y 节点点击 → ML Kit OCR 截取，全链路打通；
2. **R4 抢占可达性**（重点）：在 MIUI/HyperOS、ColorOS、OriginOS 上验证
   `TYPE_TOUCH_INTERACTION_START` 是否可达；若不可达，观察降级通道（前台突变 / 手势回调异常）能否触发熔断；
3. **双态模式**：切漫游 → 点"关注/点赞/播放"应被拦并给出协商话术；点"搜索/翻页"应放行；
4. **动态闭环**：对话中只给目标（不展开 actions）执行 `execute_macro`，观察多步闭环与 12 步熔断；
5. **经验轨迹**：同一意图连续执行两次，第二次应命中宏；手动改页面结构后应触发起始页核验失败并降级；
6. **资源熔断**：充电+高负载下观察 ≥42℃ 是否熔断截屏/漫游；
7. **保活**：将应用置后台 30 分钟以上，检查 `AccessibilityHealthMonitor` 是否识别僵尸连接；
8. **指标回收**：导出诊断包，读取单任务成功率 / 单步中位延迟 / Macro 命中率三项实测值。

## 六、已知缺口与后续建议（诚实披露）

1. **M5.0 真机验收未执行**（见第五节），M5.4（Shizuku 深化 / 虚拟副屏）未开工，且 R5 要求的副屏内存基线（激活期 ≤40MB）尚未落地；
2. **L2 云端 VLM 未接线**（保留）：`ObservationBuilder.cloudVlmProvider` 预留但生产装配传空——
   多模态通道需要独立的多模态模型配置，属于后续迭代；当前 L1 OCR 之后若仍失败则明确报 Unavailable；
3. **token 用量为估算值**（4 字符/token，偏保守），真实用量需网关在流式响应回传 `usage` 字段；
4. **漫游互动词表是词表法**，存在误伤（"关注列表"是只读入口却命中"关注"）与漏判（纯图标无描述）；
   误伤方向安全（多问一句），漏判由作用域提升前的用户协商兜底；
5. **中文正则踩坑记录**：Java 默认 `\w` 不含中文字符，"1.2万"末尾加 `\b` 会导致匹配失败——
   已在 `FastbotStateHasher` 留下注释，勿改回；
6. **锚点接地置信度 0.60**：无任何语义背书，若真机数据显示其触发率过高，说明 L0 语义裁剪丢了关键节点，应先修裁剪而非提高置信度。

## 七、交付后自查与缺陷修复（第二轮 · 2026-10-06）

> 交付后按"是否真的能用、是否真的接上线"重新逐条核对，发现 12 处缺陷。以下全部已修复并补齐回归断言。

### 7.1 正确性与安全级（P0）

| # | 缺陷 | 后果 | 修复 |
|:--|:---|:---|:---|
| 1 | L0 极速通道只识别 `Success`，把 `ConfirmationRequired` / `PermissionRequired` 当失败 | **短信/邮件/分享的二次确认被吞**：闸门装好了，用户既看不到确认卡片也不知道差在哪 | 极速通道补齐确认/授权闭环；`HelixGuiCoordinatorTest.testIntentFastPath_confirmationIsNotSwallowed` |
| 2 | 电池快照用 `Pair(temperature ?: 0f, percent ?: 0)` | 只有温度上报的 ROM 会被当成 **0% 电量**，误熔断视觉通道；反之温度未知被当成 0℃ 漏熔断 | 改为 `BatterySnapshot(temperatureCelsius: Float?, levelPercent: Int?)`，缺项各自为 null |
| 3 | 宏回放不受步数上限约束 | 一条 30 步的宏整段回放，**直接作废 §1.2.3 的 12 步有界公理** | `MacroReplayEngine.replay(maxSteps)` + 录制端 `maxStepsPerMacro=12` 双端拦截 |
| 4 | 自定义闭环给 watchdog 传 `fingerprint = 0L` | STUCK_LOOP（同页反复出现）检测**形同虚设**，卡死自愈等于没做 | 传入真实页面指纹；`attemptSelfHeal(pageFingerprint)` |
| 5 | 取消任务只改状态显示 | 用户喊停后**屏幕还在自己动** | 共享 `AtomicBoolean` 取消信号同时交给协调器与闭环；`testShareCancelSignal_stopsStaticLoop`、`testCancellationHookStopsDispatchImmediately` |
| 6 | 屏幕尺寸未知时用 `coerceAtLeast(1)` 兜底归一化 | 所有落点算成 (1000,1000)，**静默点错位置** | 尺寸 ≤0 直接 `Unavailable`；`testUnknownScreenSizeFailsInsteadOfGuessingAnchors` |

### 7.3 顺带清理

- 移除死代码 `PermissiveSafetyPolicyEngine` / `testOnlyPermissive()` 与 `SafetyRequest.UiInteraction.isNavigationOnly`（目录守卫已是唯一分类器）；
- `AccessibilityHealthMonitor` 新增 `canDispatchAutomation()`：**只有开关关闭与句柄丢失才阻断**，STALE（息屏久置无事件）仅告警——否则用户会在最需要她时吃闭门羹；
- 系统开关探测改为可注入，让四种健康态在单测里可穷举（Robolectric 下开关恒为关）。

### 7.4 明确的能力边界（不是缺陷，是刻意裁决）

- **8 个聊天层工具不变**（§二 P1-1）：新增的日历/手电筒/音量/亮度动作目前只经 `IntentActionDispatcher` 触达，**没有对应的 LLM 工具**——扩工具面属产品决策（Prompt 成本），本次严格守约束执行；
- 剪贴板读取与漫游"破例"提升是**UI/对话层触发**的能力，已提供过闸门的实例与入口（`clipboardFocusReader`、`elevateRoamingScopeForTask`），触发面随悬浮窗一并接入。
